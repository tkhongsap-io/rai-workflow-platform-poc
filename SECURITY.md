# Security handling

No deployed service or public vulnerability intake exists. For repository concerns, contact Ta through an established private channel; do not put sensitive case content or exploit credentials in public issues. A staffed intake channel, acknowledgment target and severity-based remediation windows must be approved before networked use.

Do not upload real cases to Git. Proposed data controls and failure handling are in the [threat model](docs/security/threat-model.md). Retention, permitted model providers, hosting, access groups and incident routing are unresolved release gates, not implemented controls.

Future incidents: operator contains access/notifications/model calls through controls outside the model, preserves restricted evidence and routes to the existing True security/privacy process. Actual operator runbook and restore/rollback rehearsal are mandatory before production; no executable runbook exists yet.
