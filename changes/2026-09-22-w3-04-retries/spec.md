# W3-04 adopted retry contract

Authority: [W0-07 sections 4.4–4.5](../../docs/engineering/qc-boundary-and-mail-sink.md), [W0-10](../../docs/engineering/observability-contract.md), [W3-04](../../docs/delivery/slice-1-work-breakdown.md), D06, and Ta's explicit adoption of the minimal existing-row-lock design.

Four committed attempt results, numbered 1–4. Failed results 1–3 remain queued with deadlines 1000, 5000 and 25000 milliseconds after failure completion. Failure 4 is terminal failed with no deadline. Delivered or duplicate ends as sent with no deadline/error. Persist only existing status, attempts, next_attempt_at and last_error_code. No fifth attempt after a committed terminal result. Initial rows have attempts=0 and no deadline. A queued retry without a deadline is not immediately eligible: the legacy W3-03a attempts=1 row gets one persisted adoption-time+1000ms deadline before retry selection. Do not infer failure time from created_at.

Later integration holds one notification row lock (FOR UPDATE SKIP LOCKED) through composition, one local sink call and delivery-column update in a separate transaction. Never sleep for backoff under a lock, hold a workflow/case lock, or run two initial/retry senders. Polling and startup recover persisted deadlines. Only committed outbox rows are delivered. Sink failure never undoes a committed business decision. Logs follow successful delivery-state commit and reuse the notification correlation ID.

Crash boundary: the four-result limit is not an absolute physical-invocation limit across crashes. A crash after sink invocation but before DB commit rolls back the attempt/deadline and can repeat it. File sink restart dedup relies on a completed delivery JSON; memory sinks lose accepted keys and live file-sink instances can have stale indexes. No exactly-once claim, cross-process sink guarantee, lease, external transport or new state. Bounded payload validation does not bound filesystem time; do not unlock via a timeout while the sink call remains active.

W3-07 owns Admin visibility/error presentation; W3-03b owns digest-day identity. This slice excludes digests, composition, worker wiring and error-category changes. The pure policy validates counts/dates and fails closed on invalid persisted eligibility inputs. Time is supplied by the caller; helpers have no clock, IO or state. Database locking/commit is required before their returned updates constitute proof.
