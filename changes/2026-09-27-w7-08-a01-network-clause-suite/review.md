## Deviations

- **Composition from parts, not `startServer`, in the integration suite.** Section 5.2 says the suite calls `startServer` in process. The OBS15 policy (`tests/support/integration-log-policy.ts`, asserted by `w3-int-log-coverage.test.ts`) refuses any integration file, or helper it reaches, that imports `server/src/start.ts` (only the captured submit-binding child is exempt), because `startServer` logs to stdout outside the audited log capture. Widening that exemption would weaken an existing test. As W7-07 did, `startNetworkDesk` builds the `start.ts` `network` composition from the same parts with the real `parseConfig` and the audited `buildApp`, and listens on loopback, so items 1-6 still run over the real HTTP stack. The `startServer` half (network start with both seams, readiness, fixture routes, sign-in begin) is a new case in `server/src/start.test.ts`, and item 7 spawns the real `main.ts`, which never reaches discovery. The start.test.ts path is outside the ticket's listed paths; it adds one case and changes none.
- **Accounts.** The plan names six accounts (one per role) plus a BU SPOC. Item 4's "owner reads another owner's case" needs a second owner, so the list has eight: owner A, owner B, BU SPOC CM, BU SPOC HR, AI/COE, DPO, IT Security, Admin, all `w708.*@rai-desk.example`.
- **Configuration.** The fixture loader refuses `network` mode, so the suite publishes the W1-00 configuration seed (`applyConfigurationSeed`) on the reset database and files every case through the API as owner A. Without it case creation is 422 (`useCaseGroup` not in the configured list).
- **`email_verified: false` answers 401.** Item 3 says "refused"; the verifier throws `email_not_verified` as `unauthenticated` (W0-03 ID-11), so the suite asserts 401 with no session and the `email_not_verified` audit reason, unchanged product behaviour.
- **Lane decisions carry a random `qcRunId`.** The per-lane authorization runs in `preParsing`, before the body is read, so a reviewer deciding another lane is 403 whatever the body; no lane-QC run is created for the negative.
- **Item order.** Item 6 runs before item 5 because item 5 restarts the desk.
- **BU keys.** `startNetworkDesk` lists `CM` and `HR` explicitly, as `start.ts` does from `@rai/fixtures` when that package is installed, plus the allow-list's grants.
- **W0-03 section number.** The plan names "W0-03 section 12 row ID-16"; the ID table is section 11 (section 12 is locale keys). The pointer is in the ID-16 row.
- **Acceptance line placement.** `docs/acceptance.md` had no evidence lines; a new "Evidence lines" section before "Cross-cutting negative cases" holds the dated A01 line.
- **Lane environment.** `rai-web/.env` (never committed) sets `RAI_PG_TOOLS=docker-compose:rai-ops`, as W7-01 to W7-07 did.
