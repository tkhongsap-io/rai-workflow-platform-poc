## Design choices inside the spec (for the reviewer)

- **Scripts name fixture document ids, the runner resolves row ids.** Artifact row ids are UUIDs minted by the W1-09 loader, so a script finding's artifact scope is `{ kind: 'artifact', slot, fixtureArtifactId: 'fx-doc-<case>-<slot>' }` and the runner fills `artifactId`/`contentHash` from the request's authorized artifact in that slot (W0-08 8.4: defects are "scripted against the fixture artifact ID"). The rewrites a run applies are exactly: `findingKey` (derived), `ruleRevision` (the request's), `trigger`, `provenance`, and the artifact row identity; every other field is carried unchanged, asserted field by field.
- **Fixture case resolution** is `fixtureCaseIdOf(version)`, default `version.caseId` when it is an `fx-case-*` id; W2-05 passes a resolver from the loaded fixture set. A non-fixture case yields `completed` with zero findings.
- **`upload` runs are scoped to the uploaded slot**: only the script findings on that slot apply (the source spec's "that artefact's own completeness rules"); for `submit` and `approve_attempt` every scripted finding must resolve to a request slot/artifact, or the script is a bug: `QcScriptError` is thrown (default), or the run answers `unavailable:runner_error` with the violation name when constructed with `onScriptMismatch: 'unavailable'`.
- **Simulations fire once, on the next matching call** (`'next'`, or `{ versionId }` for the next call on that version). `'hang'` waits on the caller's `AbortSignal` and then rejects with an `AbortError`, so the orchestrator's timer path is what converts it to `timeout`; `'immediate'` answers `unavailable:timeout` at once.
- **No `node:` import at all** in the substitute: scripts are static JSON imports (`tsc` copies them into `dist/`), timestamps come from an injectable `now()` defaulting to `Date`.
