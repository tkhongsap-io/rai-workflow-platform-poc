## Deviations, defaults and limitations (for the reviewer)

- **`@rai/fixtures` is not a devDependency of `server`.** W0-02 section 1.1 says it is; here `server` never imports the fixtures package (the fixture identity provider takes the user table as an input, and `fixtures` depends on `server` for the loader). A `server → fixtures → server` reference would be a cycle under `tsc -b`, and the intent of the rule, that the production build cannot contain the substitutes, is met more strongly this way (`check-substitute-absent` passes). W1-01a decides how the composition root reaches the table in `fixture` mode (a dynamic import behind the mode switch keeps `server/dist` free of it). `web` keeps `@rai/fixtures` as a devDependency for W1-13.
- **`test:integration` adds `--test-concurrency=1`** to the section-3.5 command line so that files run one at a time against the shared database (section 8.1: "reset per file"). The script name and everything else is unchanged.
- **`DATABASE_OPERATOR_URL` in tests**: `.env.example` leaves it empty (the commands then fall back to `DATABASE_MIGRATE_URL`, section 5), but a test that asserts what `rai_operator` may do must connect as that role, so `tests/support/db.ts` derives the URL from `DATABASE_URL` with the synthetic local credential the init script creates when the variable is empty, and the audit test asserts `current_user` for all three handles. Found by the clean-checkout run (the derived connection was `rai_owner` before this).
- **`.env` loading**: `config.ts` reads `rai-web/.env` when present and never overrides a variable already set in the shell, so the test commands' `NODE_ENV=test RAI_IDENTITY_MODE=fixture` prefixes win over the developer's file, as section 3.5 requires.
- **Calendar holidays are a placeholder** (five fixed-date 2026 dates) until W6 lets Admin publish the Thai public-holiday list; the `sla` and `operator_recipients` values are the recorded ones.
- **`server/dist` contains the compiled `*.test.js`** files because `tsc -b` type-checks tests and emits what it checks; harmless for the one deployable, and excluding them would remove them from `npm run typecheck`.
- **No browser spec exists**; `tests/browser/playwright.config.ts` is in place (three width projects, Chromium, the test-mode web server) so `tests/` typechecks and W1-12 can wire the check. `npm run test:browser` and `verify:full` are not claimed by this ticket (it touches no `web/` screen).
- **`main.ts` composes no identity adapter and registers no route**; W1-01a adds the adapter's `start()` and the fixture verifier behind the mode switch.
- The lane mapping is not in the configuration store (D02); the D05 rows, `lane.*`, `case.resubmit` and `finding.*` are action identifiers without rows until the W2-02 contract PR; `queue.*` and `operator.view` until W3.
