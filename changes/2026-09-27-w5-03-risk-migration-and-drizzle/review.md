## Deviations

Choices made under Ta's delegation of 2026-09-27 where the plan is silent or cannot be followed literally; each keeps the plan's contracts.

- **MIGRATION-SLOT is held by W4-11b** (#201, PR #282, `0010_w4_11b_run_extraction_identity`) at the time this PR opens. Waiting would stop the lane, which the delegation rules out, and the plan's own rule makes a number a merge-time choice. So this PR opens with `0010_w5_03_risk` (the next free number on `main` now) under a **queued** MIGRATION-SLOT claim and must not merge while W4-11b holds the slot. If W4-11b merges first, this branch rebases onto `main`, renames its SQL and journal tag to the next free number (`0011`), regenerates `meta/` by hand keeping this hand-written SQL (the CHECK replacement, the append-only trigger, the grant, the class header), merges the `w1-00-migrations` lists as a union and reruns the full gate.
- **Named table CHECK constraints** (`risk_proposal_trigger_check`, `_status_check`, `_unavailable_reason_check`, `_tier_check`, `_lowest_tier_check`, `_highest_tier_check`) instead of the sketch's inline column CHECKs: Drizzle can only express named table checks, and this keeps the snapshot equal to the SQL (a later `migrate:generate` would otherwise try to add them). Same predicates. FKs are separate `ALTER TABLE … ADD CONSTRAINT` statements with Drizzle's generated names, as in 0006.
- **rai_app is refused by privilege before the trigger.** Section 5 says "an UPDATE or DELETE on `risk_proposal` raises"; `rai_app` has no UPDATE or DELETE grant, so it gets `42501`, and the trigger's `rai.append_only` is proved as `rai_owner`. Both layers are asserted.
- **`CASE_RISK_TIERS` (the Drizzle enum tuple) gains `unknown`** so the tuple mirrors the CHECK (W0-04 "the shared enum union updated with the CHECK"). The API type `RiskTier` in `shared/src/schemas/cases.ts` is not widened here; the W5-05 row owns that (it changes `CaseView`). Nothing reads `CASE_RISK_TIERS` today.
- **W0-04 review checklist.** The checklist lists `ADD COLUMN … NULL` for frozen tables; section 5 prescribes `NOT NULL DEFAULT '{}'`. With a constant default Postgres (11+) stores the default in the catalogue and rewrites no row, and no UPDATE trigger fires (the header says so; the fixture digest of submitted versions is unchanged because no row is touched). The `case_risk_tier_check` replacement widens the allowed set, so no existing row can fail it; `case` is not a frozen table.
- **No `MIGRATION_CLASSES` entry**: W7-03 has not merged (no such constant on `main`), as section 9 allows.
- The `w1-00-migrations` test title (which lists earlier tickets) is not changed; only its lists are.
