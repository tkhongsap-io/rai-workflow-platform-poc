# W3-03b producer and loader specification

Based on fadc39e and 07a migration 0007. The operational producer writes a running sla_digest job before querying W3-05. It freezes digestDay from startedAt in Asia/Bangkok. Job breachCount counts overdue lane entries; rendered message count counts distinct cases. Recipient addresses come from the operator_recipients revision effective strictly before job start, never roles. Thai is the default; an injected service locale enables English with the same shared keys.

Empty results complete count 0 with no notification or link. Nonempty results freeze validated breaches, locale and configuration revision ID in immutable templateParams. Render contains case IDs, lane labels, Gregorian due dates and sign-in-required canonical case links, not case documents or finding evidence. Each lane entry has one indexed link as required by the sink, even when several lanes reference the same case. At most 500 entries and 64KiB body; larger renders fail safely rather than silently omit cases.

Each recipient's notification and job link commit atomically. Only the exact unique day/recipient constraint is treated as a duplicate; other enqueue failures fail the job. Concurrent same-day runs can each own a subset of recipients; each reports only its own committed notification IDs. Already committed recipient rows survive a later recipient failure and retain original run provenance. New days may enqueue again. No row is delivered by the producer. Completed/failed records and safe query/render/enqueue logs share original correlation. A crash before terminal recording leaves running visible, never inferred complete.

loadCommittedDigestRequest(tx,row,{publicBaseUrl}) re-reads the stored notification by ID and joins immutable job/link. It verifies digest event/null case/version/lane, persisted day/recipient/correlation, run start/day and enqueue time; validates the frozen configuration reference and recipient membership; verifies snapshot versions belong to cases and were submitted by run start, and recomputes due dates from frozen SLA/calendar. It does not re-run current pending-lane selection on retries because workflow may since have advanced. Snapshot plus committed job linkage is historical authority. It reconstructs required DigestJobProvenance; no human business audit is created. Caller fields other than ID cannot supply authority.

createDailyDigestSchedule is a standalone producer lifecycle adapter: startup run, then next Bangkok midnight; no overlapping local run. A run spanning midnight schedules the new day immediately after settlement. The supplied AbortSignal stops timers and new work; supplied track(task) integrates with the bounded shared drain. Cancellation never races DB work. No retry policy, transport or second dispatcher loop is added. The parent-approved app/start binding runs this producer before the existing dispatcher startup and shares its bounded drain.
