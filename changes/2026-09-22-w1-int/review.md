## Deviations, defaults and limitations (for the reviewer)

- **Where the journey runs.** The plan allows the restart journey as a node:test integration journey or a Playwright spec that controls the process; it is the latter (`w1-int-journey.spec.ts`), so the UI is what is driven and the restarted process is the built deployable that `npm start` runs. The W1-05 restart recipe over the direct API (`w1-05-restart.test.ts`) stays as it was.
- **`workers: 1`** in the evidence configuration: one real database is shared by every spec. Each mutating spec resets it to the fixture set before every test (about half a second each); the whole evidence run is 1.3 minutes locally.
- **`start.ts`** refuses to start in production without a web build (`missing:web/dist`, exit 78). The plan lists no such row; it follows the fail-closed rule (a misconfiguration is a start-up failure, never a default) and is unit-tested. Development and test serve the API alone without a build, so the existing integration suites are unchanged.
- **Helmet on error replies.** The authorization `onRequest` hook is added synchronously at the root and runs before helmet's (a plugin hook), so a 401 thrown there carries no helmet headers; every page, asset, successful API answer and root not-found answer does. The artifact download route keeps its own stricter headers (`Content-Security-Policy: sandbox`).
- **Keyboard-only in the journey**: the sign-in and submit steps are driven by keyboard with a visible-focus assertion; the slot dialogs and the form are driven by role and label because the promoted W1-06 and W1-07 specs already prove every one of those controls by keyboard at the three widths on the real server.
- **`base_url_not_loopback`**: the negatives include a non-loopback `PUBLIC_BASE_URL` for `local-google`; the adapter answers with the W0-03 S3 code, not `bind_not_loopback`, and the test asserts that code.
- **Scan scope of "no test imports the substitute"**: the W1-13 API substitute (`fixtures/src/substitutes/api/`), its marker and its test server. The in-process QC and mail-sink substitutes (W1-10, W1-11) are what the integration layer binds by design (W0-02 8.1) and are not flagged.
- **Board**: no CLAIM appended by this run; the harness records board and log entries at the merge step.
