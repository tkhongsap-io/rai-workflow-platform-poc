# W3-08 substitute implementation of the W3-01 queue contract

GET /api/queue uses the existing case.list action and mandatory authenticated actor scope. Existing GET /api/cases remains compatible. This specification inherits the merged W3-01 shared contract; W3-08 implements the dev/test substitute route, while W3-01 implements the real-server route.

TypeBox query and TypeScript response: rai-web/shared/src/schemas/queue.ts. Defaults: page 1, pageSize 25, searchBy all. Unknown parameters, invalid enums and out-of-range integers are invalid_input. Filter predicates are ANDed. Search is trimmed, NFC-normalized, case-insensitive literal substring (escape SQL wildcard characters), empty means no search. all searches case name, registry ID, external ID/Unknown, status key, owner display name, owner subject ID and use-case group. Named searchBy limits to that field; owner searches both stored business_owner display name and owner_subject_id. Display names never determine authorization. Status filter uses the existing derived status, not the coarse stored desk_status. Owner/group filters are exact matches. Thai text must match.

Scope is applied before search, total, statusCounts, filterOptions and pagination. Out-of-scope filter values yield empty results without exposing their existence. statusCounts and distinct sorted filterOptions are from the actor-visible population before optional filters; total is the filtered population. Sort updatedAt descending then caseId descending; an empty page remains valid. Status counts include all five states with zeros. Read each response from a consistent database snapshot.

Each QueueItem extends CaseSummary with external source ID, ownerDisplayName (stored business_owner), latestVersionNumber (draft if present, otherwise submitted), current submitted-version lanes and due dates from W3-05. A successor draft does not pretend new lanes opened: the existing submitted version's lane state and historical due dates remain visible. No lanes before first submission. nextAction maps derived status to prepare_pack, correct_pack, review_lanes, resolve_findings, review_complete; it is a case-level cue, never action authorization. UI uses locale keys. All reads and case deep links retain existing access checks.

Tests required for implementation: every search key, combined filters, all role scopes including no-scope, out-of-scope counts/options equivalence, pagination, literal wildcard search, Thai normalization and Thai owner-name search distinct from subject ID, current versus successor version, all derived statuses including awaiting_disposition, and frozen SLA consistency. No production claim.
