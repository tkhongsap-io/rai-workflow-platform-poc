## Deviations, defaults and limitations (for the reviewer)

- **`businessOwner` is required on create.** W0-02 7.3 types `businessOwner: SubjectId` as a required field of `CaseWritableFields` while the prose says it "defaults to the actor for role owner" and, for a SPOC, "absent, it defaults to the actor". The schema is kept verbatim (required); an owner sends its own subject id (the scope step makes any other value 403), and a SPOC names the owner. Making it optional is a 7.3 contract change for the lead; the substitute (W1-13) and W1-07 should send it.
- **Configured BU keys.** No `business_units` configuration kind exists (W0-04 fixes the kinds). Slice 1 uses the W0-04 rule as written: the fixture BU list (`CM`, `HR`; `FIXTURE_BUSINESS_UNITS` in `fixtures/src/data/users.ts`), loaded at start in every identity mode, so a `local-google` account (owner by W0-03 4.1) can file a case in W1-08's manual walkthrough. Only the keys cross the boundary; the fixture identities stay fixture-mode only. In an install without the fixtures package (production) the list is empty until the W6/W8 group mapping supplies BU keys; the local role map's `business_unit` grants are not a BU source (a key outside the fixture list would break the recorded rule). Recorded here rather than inventing a configuration kind.
- **Subject resolution for `businessOwner`.** No directory exists in slice 1; a subject resolves from the fixture identities, the acting principal, or any subject that has signed in (the `session` table's principal snapshot). A never-seen subject is 422 `validation.subject_unresolvable` (W0-05 "Create target": "a named subject that does not resolve … is 422").
- **Draft v1 defaults.** `stage_context = 'idea'` and `checklist_template_version` = the first configured entry (`v1.0 Sheet3`), both editable through W1-04's `PUT /draft`; 7.5 owns the draft and may change the default.
- **Idempotent create without a case lock.** The W0-04 recipe locks the case row; a create has none, so the (actor, key) pair is serialised with a transaction-scoped advisory lock. W1-05's `withWorkflowTransaction` generalises the recipe in `versions/`; `cases/idempotency.ts` is the create-only slice.
- **`refreshPath`** is `/cases/<caseId>` (the SPA path W1-06/W1-07 will serve); W0-06 8.2 asks for a relative app path and names no route.
- **`version_superseded` / `version_closed` tests** write the rows a submit leaves behind directly as `rai_owner` (W1-05 owns submit); the fixture set itself stays unsubmitted (W0-08 8.1 rule 4).
- **Substrate notes for the lead (not this ticket):** (1) `shared/src/schemas/artifacts.ts` `AllowedMediaTypeSchema` and `shared/src/schemas/slots.ts` `StageContextSchema` use the same `.map(Type.Literal)` form that infers `never` (W1-03 and W1-04 will hit it as W1-01 and this ticket did); (2) the W1-00 error handler still maps Fastify's malformed-JSON error to 500 `internal_error` where W0-06 8.1 says 422 `invalid_input` (W1-01 review noted it; the "malformed JSON body" test here asserts only that nothing is written).
- **Not in this ticket:** search, filters, counts (W3-01); slot edits (W1-04); submit (W1-05); `allowedActions` on reads (W0-02 section 13); `request.completed` log line (W3-07). No dependency added; D07-D10 untouched; the frozen source spec unread for edits.
