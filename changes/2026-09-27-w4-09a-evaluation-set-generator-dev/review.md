## Change

- **`fixtures/src/generate/deflate.ts`** (new): a fixed-Huffman DEFLATE encoder (literals only, one final block), a zlib wrapper and Adler-32. FlateDecode PDF streams and deflated ZIP parts use it, so the bytes do not depend on the platform's zlib build (Node 24 ships Chromium's zlib, whose SIMD paths can differ between the arm64 laptops and the x86 CI runners, and the manifest pins every digest).
- **`fixtures/src/generate/pdf.ts`** (additive): `buildPdfDocument({ title, commentLines, pages, compression, brokenXref })`. Pages are text (Helvetica; ASCII lines as literal strings, other lines as UTF-16BE hex with BOM), image (one image XObject, no text operator) or CID (a Type0 `Identity-H` font with no `ToUnicode`, glyph codes only). `flate` compresses every stream; `brokenXref` shifts every offset and `startxref`. `buildPdf` and the slice-1 bytes are unchanged.
- **`fixtures/src/generate/ooxml.ts`** (additive): `buildDocx(lines, { doctype?, method? })` (without options, byte-identical to before), `buildZip` with a per-entry `stored`/`deflate` method, `buildXlsxWorkbook` (several sheets, shared strings, numeric cells, a stored `docProps/core.xml` title so the provenance marker stays greppable), `columnName`.
- **`fixtures/src/evaluation/`** (new): `types.ts`, `vocabulary.ts` (the dev rendering of the claim grammar), `cases.ts` (26 dev cases), `render.ts` (renderers returning each claim's locator in the W4-16 shape), `labels.ts` and `labels/ev-dev-01..26.json`, `generate.ts` (the CLI), `manifest.json`, `README.md`.
- **`fixtures/src/provenance-denylist.ts`** (new): the slice-1 denylist moved unchanged (verified with `diff` against the old block) so both provenance tests use one list; `data/provenance.test.ts` imports and re-exports it. It sits outside `data/`, so the `slice1-synthetic` set hash is unchanged (its manifest test passes unchanged).
- **`package.json`**: `fixtures:eval:generate`.
- **Tests** (+50 unit tests, all under the existing `fixtures/src/**/*.test.ts` glob): `generate/deflate.test.ts` (4), `evaluation/render.test.ts` (12), `generate.test.ts` (8), `labels.test.ts` (11), `coverage.test.ts` (11), `provenance.test.ts` (4).

`labels.test.ts` never computes a finding. It checks each label against its case row and the plan's scope rules: the run list (uploads of attached slots 1, 2, 5; submit; one attempt per lane; both parts), unavailable parts carry a reason and no findings; the metadata part is always completed and holds only metadata rules on their triggers and slot states; a content part is unavailable exactly when a slot it reads (plan 3.1/3.3 read table, decisions 22 and 28, `model_type` routing) holds an unreadable document; approve-attempt findings are owned by the run lane and DPO/IT-Security attempts never cite slot 1; content rules only on their triggers, template and model type; every labelled locator is a claim position the renderer placed (grounding), or `absent` for a missing classic-ML claim; no duplicate (rule, scope, claim) in a part.

How the labels were written: per case, the agent team wrote the expected findings of each run by hand (which rule, lane, slot and which claim of the document), and the locator positions were read from the renderer's claim order. The JSON files are the committed record; nothing regenerates them.

## Deviations

- **One new helper file outside the named paths:** `fixtures/src/generate/deflate.ts` (and its test). The plan names `fixtures/src/generate/{pdf,ooxml}.ts`; both use the encoder, so it has its own module. Reason: platform-independent bytes (see Change).
- **The denylist moved** to `fixtures/src/provenance-denylist.ts` so the new provenance test does not import a test file (which would re-register its tests). Content unchanged; `data/provenance.test.ts` re-exports it and passes unchanged.
- **`manifest.json` `split` is a list** (`["dev"]`). The plan names the field; a list lets W4-09b add `heldout` to the same manifest without renaming it. W4-09b may choose otherwise.
- **Label assumptions** where the plan leaves a detail to W4-06a-d (recorded in the [spec](spec.md)): Thai documents use English keys with Thai questions and answer words (Thai keys are held-out renderings, plan 11.1 "Split"); a reasoned N/A carries its reason in `evidence`; `ACC-CLASSIC-ML-METRIC` cites the first performance claim, else `absent`; an extraction metric on a hallucination claim also raises `ACC-METRIC-CITED`; the Thai CID-font PDF is labelled `artifact_unreadable` as plan 11.1 says, which assumes W4-05d refuses an `Identity-H` font without `ToUnicode` (plan 4.3: CID-font Thai is not decoded). If a rule's params or the extractor end up differing, W4-09b records a disagreement; labels are not changed to fit an output.
- **Uploads labelled only for slots 1, 2 and 5.** No content rule reads another slot and no metadata rule runs on upload, so an upload elsewhere is two empty completed parts; W4-08a can add them mechanically if it wants the count.
- **Filler documents.** Attached slots other than 1, 2 and 5 hold a one-line DOCX so a case can also be uploaded whole through the UI (plan section 13); no rule reads them.
- **Known follow-up, not in this ticket:** W5-10 adds `RISK-TIER-UNKNOWN` to every answerless submit's metadata part (W5 plan section 9). When it merges, whichever of W5-10 and W4-08a lands second adds that finding to the submit metadata labels (every dev case is answerless) and refreshes the manifest.
