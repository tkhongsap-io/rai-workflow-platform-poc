Done when:

1. **Layout** under `rai-web/fixtures/src/evaluation/`: `cases.ts` (case rows), `render.ts` (document renderers over `fixtures/src/generate/{pdf,ooxml}.ts`), `labels/<case>.json`, `manifest.json` (`{ name, version, sha256, split, documents }`), `generate.ts` (the CLI), `README.md`.
2. **Generation.** `npm run fixtures:eval:generate` writes every document to `rai-web/.local/eval-fixtures/qc-eval-synthetic@1/<split>/<case>/slot-<n>/<filename>` (gitignored), checks each SHA-256 against `manifest.json` and prints `qc-eval-synthetic@1 <sha256[0:12]>`; `--write-manifest` refreshes the manifest; `--out <dir>` overrides the output root. **Deterministic:** two runs give the same bytes (unit test over two temporary directories; review records two CLI runs). No bytes are committed.
3. **Renderers** (additive; the `slice1-synthetic` bytes and manifest are unchanged):
   - PDF: several pages, several text lines per page, no filter or `/FlateDecode`; an image-only page (scanned); a Type0 `Identity-H` font with no `ToUnicode` carrying Thai glyph codes (CID font, not decodable); a broken cross-reference table (malformed).
   - OOXML: several paragraphs (DOCX) and rows over several sheets, shared strings and numeric cells (XLSX); stored or deflate ZIP entries; a DOCX whose part carries a `<!DOCTYPE` (malformed).
   - FlateDecode and deflate bytes come from a fixed-Huffman encoder written here, so the bytes do not depend on the platform's zlib build.
4. **Coverage.** Every item on the fixture list of section 11.1 has at least one dev case: Thai and English; DOCX, XLSX, text-layer PDF, scanned PNG, scanned image-only PDF, malformed; `v1.0 Sheet3` and `v2.0`; `llm`, `classic_ml`, `other`; missing, not-yet and N/A at each of `idea`, `pre_build`, `pre_launch`; conflicting BRD (slot 5) and privacy (slot 2) entries; extraction-only "Yes"; valid metric evidence; band values below, equal and above each tier; a Thai CID-font PDF; injection and exfiltration documents. Also: an unreadable slot 2 and an unreadable slot 5, each with metadata labels, and a scanned slot 1. A unit test checks the coverage from the case rows (format, language, template, model type and slot states are read from the data, not from tags).
5. **Labels** (`labels/<case>.json`), per case: every upload of an attached slot 1, 2 or 5, the submit, and one approve attempt per lane (AI/COE, DPO, IT/Security). Each run has both parts, `deterministic` (metadata rules) and `content`, with `status`, `unavailableReason` when unavailable, and findings (`ruleId`, `owningLane`, `scope`, evidence slots and locator kind and position; the fact for `PACK-CONTRADICTION`). `labelledBy` is exactly `agent-team, provisional (Ta delegation 2026-09-27); lane-expert sign-off pending (D09)`. Unit tests check, over every case:
   - an unavailable part carries no findings; a completed part carries no reason;
   - decision 28: no content finding on a DPO or IT/Security approve attempt cites slot 1, and every approve-attempt finding is owned by the run's lane; a case with an unreadable slot 1 labels the AI/COE content part `unavailable` and the DPO and IT/Security content parts `completed` (when slot 5 is readable or absent);
   - rule scope: metadata rules only in `deterministic` parts and content rules only in `content` parts; `ACC-BAND-V1-SHEET3` never on `v2.0`; `ACC-CLASSIC-ML-METRIC` only on `classic_ml`, and the other `ACC-*` rules never on it; content findings on upload only for slot 1;
   - grounding: every labelled content locator is the locator of a claim the renderer placed in that slot's document, or `absent`.
6. **Provenance.** A test greps every evaluation source file, label and README, and every generated byte (UTF-8 and Latin-1), against the `slice1-synthetic` denylist, which moves unchanged into a module both tests import.
7. Full plan section 16 gate green.

Label assumptions (the rules' `params` are written by W4-06a-d; where they differ from these, W4-09b records the disagreement, and a label is not quietly changed to fit an output):

- Dev renderings: English keys in the fixed order `item, question, answer, metric, value, denominator, threshold, evidence, tier`, `key: value` pairs joined by `; ` (DOCX, PDF) or one column per key under a header row (XLSX); answers `Yes`/`No`/`N/A`, in Thai documents `ใช่`/`ไม่ใช่`/`ไม่เกี่ยวข้อง`; hallucination values in percent. `vocabulary.ts` lists every key, answer word, item keyword and metric the dev split uses, so W4-06a-d can check their label lists cover it.
- A reasoned N/A carries its reason in the `evidence` field (the grammar's column keys have no `reason` key).
- `ACC-CLASSIC-ML-METRIC` cites the first `classic_ml_performance` claim when one exists, and `absent` on the artifact otherwise.
- An extraction metric on a hallucination claim also raises `ACC-METRIC-CITED` (plan 3.3: "an extraction metric counts as absent here").
