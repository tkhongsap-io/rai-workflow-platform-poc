## Deviations, defaults and limitations (for the reviewer)

- **`default_non_vendor` from the client.** 7.5 calls it "the server-set reason for slots 3 and 4 when vendorInvolved is false"; the shape admits it in a request. The server accepts it only where it would set it itself (slot 3 or 4, non-vendor case) so a save that echoes the draft back is idempotent, and answers 422 `reason_required` anywhere else, since "never when true" and "reason mandatory for N/A" leave no other reading. The W1-13 substitute accepts it on any slot; the server is right and the substitute is not edited here (one ticket per PR).
- **Projected fields on PUT.** W0-06 4.2 lists "inherited status field write" under `invalid_input` for save draft; the 7.5 table does not repeat it. The PUT reuses the W1-02 check (`error.invalid_input.projected_field`). The substitute ignores an unknown top-level key on PUT; again the server is right.
- **Flip to false.** 7.5 describes the defaults at draft creation and the false → true reversion only; flipping `vendorInvolved` back to false applies no default to a slot the owner may have set since. Recorded as a default, not a decision; the UI (W1-06) can offer the default reason as a choice.
- **`max_pack_mb`** is `UPLOAD_MAX_PACK_BYTES / MiB` as in the W1-03 pipeline (150 for the configured limit); the substitute floors it (same value at 150 MiB).
- **W1-10 is not on `main`.** The hook point exists and is bound to the no-op; binding the substitute waits for the orchestrator ticket. Nothing in this ticket labels QC as implemented.
- **"The same artifact attaches to a later version of its own case"** (W0-04 proof table, second half) needs a submitted version and a successor draft (W1-05, W2-03); the same-draft half is proved here.
- **No migration.** W0-04 says W1-04 "may additionally" back the case binding with a composite FK; the required repository check is in place and tested. A follow-up migration can add `UNIQUE (id, case_id)` and `artifact_slot.case_id`.
- **Audit `slots` list on a context-only save** is `[]` (present, empty), so the event shape is one shape for every save.
