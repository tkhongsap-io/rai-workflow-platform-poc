Source: W6 plan sections 2.1 (kinds, "Not frozen"), 2.3 (drafts, publish, restore, change note), 3 (the W6-02 migration, the `DELETE` grant, `BUSINESS_TABLES`, shared registration, registered versus seeded kinds, the contract test), 10 (audit actions), 11 (the W6-02 row), 11.2 (migration numbering, seed and schema shared-file rules) and 17 (the W0-04 amendment). The plan wins over issue #214.

Done when:

1. **Migration** `server/drizzle/0011_w6_02_configuration_admin.sql` (the next free number on `main` when the branch was cut; renumbered by hand at rebase if another migration merges first) with the house header and `-- rollback expectation: restore-required; …`. Nothing touches existing rows:
   - `configuration_revision.change_note text` with `configuration_revision_change_note_check` (`NULL` or 1-500 characters);
   - `configuration_revision.restores_id uuid` FK to `configuration_revision(id)`;
   - `configuration_revision_kind_check` dropped and re-added with `desk_controls`;
   - `configuration_draft` (`kind` primary key with the same kind CHECK, `base_revision_id` FK, `body jsonb NOT NULL`, `change_note` with the same CHECK, `draft_version integer NOT NULL CHECK >= 1`, `updated_by`, `updated_role`, `updated_at`);
   - `GRANT SELECT, INSERT, UPDATE, DELETE ON configuration_draft TO rai_app`; `configuration_revision` grants and the `configuration_revision_frozen` trigger unchanged.
2. **Drizzle**: `db/schema/configuration-revision.ts` gains `changeNote`, `restoresId`, `desk_controls` and the change-note CHECK; new `db/schema/configuration-draft.ts` exported from `db/schema/index.ts`; `meta/_journal.json` and `meta/0011_snapshot.json` generated by `npm run migrate:generate`, the SQL body then replaced by the hand-written SQL; a second `migrate:generate` reports no changes.
3. **Shared registration** (`shared/src/schemas/cases.ts`): `'desk_controls'` in `CONFIGURATION_KINDS`, `DeskControlsBodySchema` (`{ writesFrozen, mailPaused, qcPaused }`, booleans, no other property), its `CONFIGURATION_BODY_SCHEMAS` entry and its `ConfigurationBodies` type; `CONFIGURATION_VALUES_OWNER.desk_controls = 'admin'`. A unit test asserts the shared and db kind lists are equal.
4. **Seed** (`configuration/seed.ts`): `UNSEEDED_KINDS = ['group_role_mapping']`, `ConfigurationSeed` over `Exclude<SeedableConfigurationKind, UnseededConfigurationKind>`, `desk_controls` seeded all `false`. `seed.test.ts` asserts the seeded set by kind (the six W1-W4a kinds plus `desk_controls`) and that no `UNSEEDED_KINDS` member is seeded.
5. **Freeze** (`versions/freeze.ts`): `UNFROZEN_KINDS = ['desk_controls', 'group_role_mapping']`, skipped by `resolveFrozenConfiguration`; a unit test. `w1-05-submit.test.ts` asserts the frozen kinds by name (every seeded kind in force except the unfrozen ones).
6. **Store** (`configuration/store.ts`), all under the per-kind advisory lock `publishRevision` uses, each in the caller's transaction:
   - `readDraft(exec, kind)`;
   - `saveDraft`: any JSON object up to `CONFIGURATION_DRAFT_MAX_BYTES` (Q18; larger or not an object is refused); `expectedDraftVersion` `null` creates, a number updates; a mismatch is `ConfigurationChanged`; `draft_version` increments; audit `configuration.draft_saved`;
   - `discardDraft`: version check, delete, audit `configuration.draft_discarded`;
   - `publishDraft`: version check and "the kind's current revision is still both `expectedCurrentRevisionId` and the draft's base" (otherwise `ConfigurationChanged`), a change note (the request's or the draft's; none is refused), `validateConfigurationBody`, `publishRevision` with the note, delete the draft, audit `configuration.published`;
   - `restoreRevision`: revision K of the kind (else `ConfigurationRevisionNotFound`), current check, K in force refused (`ConfigurationRestoreCurrent`), required note, `validateConfigurationBody` on K's body, publish N+1 with `restores_id = K`, audit `configuration.published` with `afterRef.restores_configuration_revision_id`; an existing draft is kept.
   - `publishRevision` gains optional `changeNote` and `restoresId`; seed and fixture callers are unchanged. The store still exports no function whose name says update or delete.
7. **Audit**: `AUDIT_ACTIONS` gains `configuration.draft_saved` and `configuration.draft_discarded`. Refs hold IDs, kinds and numbers only; the note is on the row.
8. **Integration tests** (`tests/integration/w6-02-configuration-drafts.test.ts`, real Postgres): save, update, discard, publish, restore; stale 409s (draft moved, base moved, current moved); the draft consumed on publish; restore N+1 with its link; restore of the revision in force refused; a missing change note refused; the trigger still blocks `UPDATE`; audit rows. `w1-00-migrations.test.ts`: table list, the grant list with `configuration_draft:DELETE|INSERT|SELECT|UPDATE` (the only `DELETE`), the amended roles comment, `rai_app` can delete a draft and still cannot update a revision.
9. **Reset**: `tests/support/db.ts` `BUSINESS_TABLES` gains `configuration_draft` before `configuration_revision`.
10. **W0-04 amended** (`persistence-and-artifact-store.md`): the roles table and the "Deletion" row ("no `DELETE` on any table except `configuration_draft`"), the new columns, the `configuration_draft` entity and the `desk_controls` kind, as a dated note.
11. `MIGRATION_CLASSES` entry only if W7-03 has merged (not on `main` at branch time).
12. Full W6 plan section 12 gate green.
