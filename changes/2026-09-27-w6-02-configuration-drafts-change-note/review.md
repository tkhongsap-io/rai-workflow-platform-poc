## Deviations

Choices made under Ta's delegation of 2026-09-27 where the plan is silent; each keeps the plan's contracts.

- **"Current revision" for the optimistic checks is the kind's latest published revision** (highest `revision_number`), not `currentRevision(at)`. Under `after_publish` the two differ only within the publish instant itself; the latest row is what a concurrent publish changes, so it is the right thing to compare. `restore_current` compares against the same row.
- **Error classes** (not named by the plan): `ConfigurationChanged` (→ 409 `configuration_changed`; its `current` matches `ConfigurationStaleDetails.current`), `ConfigurationDraftRejected` (→ 422; reasons `not_an_object`, `too_large`, `base_revision_unknown`), `ConfigurationChangeNoteInvalid` (→ 422), `ConfigurationRevisionNotFound` (→ 404 `configuration`), `ConfigurationRestoreCurrent` (→ 422 `restore_current`), plus the existing `ConfigurationBodyInvalid`. W6-04 maps them.
- **A saved draft's base must be a revision of the same kind** (or `null`); anything else is refused at save rather than failing later. A malformed revision ID is treated as unknown (404 on restore), never a database error.
- **A blank (whitespace-only) change note is refused**, beyond the 1-500 length rule: a person's note must say something.
- **Validation on publish is `validateConfigurationBody`** (schema plus `qcRulesBodyProblems`). W6-03 adds `publishProblems` to `publishDraft` and `restoreRevision` (its row lists `store.ts`); `publishRevision` stays unchanged, as section 2.4 requires.
- **Log events** (`configuration.published`, `configuration.publish_refused`, section 10) are not emitted here: the store has no logger and the events belong to the request that W6-04 serves. The audit events are written here.
- **`publishRevision` checks a change note when one is passed**, so a direct caller cannot store a note the CHECK would refuse with a less clear error.
- **The Drizzle kind CHECK is built from the constant** (`CONFIGURATION_KINDS_SQL`), so the db list, both CHECKs and the snapshot cannot drift; the migration SQL keeps the literal list.
- **MIGRATION-SLOT**: other migration PRs are open (W4-11b #282). This PR opened with `0011` under a queued claim; W7-03 (#287) merged `0011_w7_03_migration_class` first, so round 1 rebased onto `main` and regenerated the migration by hand as `0012_w6_02_configuration_admin` (see "Round 1"). It must not merge while another migration PR holds the slot.
- **Local environment**: `rai-web/.env` (never committed) also sets `RAI_PG_TOOLS=docker-compose:rai-admin` (this lane's compose project). The first integration run used the example value `docker-compose:rai-dev`, and the four W7-01 backup tests failed with `pg_tools_container_not_found`; with the lane value they pass, and the whole suite was rerun green (below).

- A database seeded before this PR has no `desk_controls` revision; W6-17 treats a missing body as every switch off (plan section 7).
