# Intent: questionnaire UI in the pack editor (W5-07, #230)

W5-04 lets the owner or BU SPOC store risk answers on the pack draft and W5-05 scores them at submit, but nobody can see or answer the questionnaire in the desk yet. This ticket puts it in the pack editor: the seven questions of the rubric in force as radio groups with "Unknown / not yet known" and a clear button, a hint naming the evidence slot each answer cites and that slot's current state, who gave each saved answer, and a live preview of the tier computed in the browser by the same shared engine the server runs at submit, labelled as a preview that is recorded only at submit. Answers are saved by the existing "Save draft" request, together with slot and settings changes.

The rubric is still the labelled **SYNTHETIC PLACEHOLDER** (D07 stays with AI/COE), so a shared banner says so wherever the questionnaire shows. The rubric read is optional to the rest of the screen: when it answers 404 (a database without a rubric, or an older substitute) the editor shows a one-line "risk questionnaire not configured" note and every existing control keeps working. The in-memory API substitute gains the rubric read (R-16), so the substitute demo shows the questionnaire too.

It is order 5 in section 9 of the [W5 plan](../../docs/engineering/implementation-plan-w5.md) and implements section 7 ("Placeholder banner", "Missing routes and the substitute", "Pack editor", the `risk.*` locale keys it needs) under the register rows "Ta's delegation (2026-09-27)" and "W5 delegated rulings (provisional)" (R-2, R-4's preview, R-13, R-16). The version view, reviewer and overview display is W5-08; queue chips are W5-09. The preview is never recorded and grants nothing. Synthetic data only; no network call; no deploy.
