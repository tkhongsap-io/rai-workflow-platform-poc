## Change

- **Registered kind** (`shared/src/schemas/cases.ts`): `CONFIGURATION_BODY_SCHEMAS.risk_rubric = RiskRubricBodySchema`, `ConfigurationBodies.risk_rubric = RiskRubricBody`, and the `RiskRubricView` response type `{ revisionId, label, provenance, publishedAt, body }`.
- **Validated on publish** (`server/src/configuration/store.ts`): one `if (kind === 'risk_rubric')` branch in `validateConfigurationBody` running `riskRubricBodyProblems` after the schema, like `qc_rules`. New read `currentRiskRubric(exec, at)` over `currentRevision` (the W1-00 activation rule).
- **Placeholder seed** (`server/src/configuration/seed.ts`): revision 1 `synthetic-placeholder.1`, `provenance: 'synthetic_placeholder'`. Seven invented questions (people affected, automation of decisions, personal data, external exposure, vendor or model provenance, reversibility, monitoring), each text prefixed `[SYNTHETIC PLACEHOLDER]` in Thai and English, three options (low, medium, high) each, `evidenceSlot: 1` on every question. Personal data `yes` escalates to Medium only. Rules: High at >= 3 high; Medium at >= 1 high or >= 2 medium; otherwise Low. Tier labels High/Medium/Low/Unknown with Thai. The header says every value is a D07 placeholder.
- **Rubric read** (`server/src/cases/routes.ts`): `GET /api/configuration/risk-rubric/current`, `config.read_effective` (every role), 200 `RiskRubricView` or 404 `not_found` (`risk_rubric`). `NotFoundResource` (`shared/src/errors.ts`) and the `not_found` log `targetType` values (`shared/src/schemas/observability.ts`) gain `risk_rubric`.
- **Freeze**: no code change. Every new submit's `frozen_configuration` names the `risk_rubric` revision because the seed now publishes it; `configuration_revision_id` stays the `qc_rules` revision (`versions/freeze.ts` prefers it).
- **Spec amendment**: W0-02 (`implementation-plan-w1-w3.md`) section 7.3 gains the dated "W5-02 amendment (2026-09-27): the risk rubric read" note with the endpoint row.

## Deviations

Choices made under Ta's delegation of 2026-09-27 where the plan is silent; each keeps the plan's contracts.

- **Placeholder option values and texts** are the agent team's invention (the plan names topics only): e.g. RQ1 `few`/`many`/`public`, RQ3 `no`/`yes`/`sensitive`. All D07-owned; replaced by D07's revision.
- **RQ3's `yes` is level `medium` with `escalatesTo: 'medium'`**, and the high option is `sensitive`. The plan asks for three options at low, medium and high on every question and for `yes` to escalate to Medium. With `yes` at level high the escalation would never change a tier (one high answer is already Medium), so `yes` sits at medium, where the escalation is what lifts an otherwise all-low set to Medium; a test proves it.
- **`not_found` resource `risk_rubric`** is added to `NotFoundResource` and to the `SafeErrorFields` `not_found.targetType` values (W0-10 log schema), since the plan's 404 names that resource and the error capture logs it as `targetType`. No other log shape changes.
- **The route sits in `cases/routes.ts`** next to `GET /api/configuration/current`, as the plan's "Main paths" column says, not in a new `configuration/routes.ts`.
- **The in-memory API substitute is unchanged**: R-16 assigns its rubric read to W5-07. No web code reads the endpoint yet.
- **Local `.env` only**: `RAI_PG_TOOLS` was set to `docker-compose:rai-risk` (this lane's compose project) instead of `.env.example`'s `rai-dev`; see the command table. `.env` is not committed.
