## Deviations, defaults and limitations (for the reviewer)

- **HRR and "agents may not change CI".** This ticket's owner type says agents do not change CI; the brief assigned the ticket to an agent for drafting, as W1-00 (also HRR) was. The workflow is inert until a human merges it, and any later edit to `.github/`, `scripts/` or `docker-compose.yml` is a lead PR (section 6). Recorded so nobody reads this PR as an agent having changed CI on its own.
- **Branch protection is not set** (see the table above). Until the lead requires `required` on `main`, CI runs on every PR but does not block the merge button.
- **Postgres in CI is a GitHub service container**, as section 6 words it ("Postgres 16 as a service container"), not `docker compose`; the image pin `postgres:16.15-alpine` is therefore stated twice (compose and `ci.yml`), and the W0-04 roles are created by running the same `docker/postgres/init/001-roles.sql` into the service with `docker exec`, so there is one source of truth for the roles. Switching CI to `docker compose up --wait` is a one-step change if the lead prefers a single pin.
- **`NODE_ENV=test` is set on every job except `build`.** Section 6 says every check runs with `NODE_ENV=test`; a Vite build under `NODE_ENV=test` would not produce the production bundle that `check-substitute-absent` must inspect, so the build job leaves it unset (Vite then builds for production). The test commands set `NODE_ENV=test` themselves in any case.
- **Playwright readiness is the port, not `GET /healthz`.** W1-00's config polled `${baseURL}/healthz`, which does not exist until W3-07a and which Playwright treats as "not ready" while it answers 404; the config now waits for the port to accept (the process listens only after `config.ts` accepted the environment). W3-07a switches back to the URL form.
- **The harness spec audits synthetic documents set on the page**, not product screens: none exist yet (W1-07, W1-06). The helpers are the ones those specs will call; the product screens are audited when they arrive. The runner's `port` of the SPA is the API's, and the SPA itself (`web/dist`) is not yet served by the API (`server/src/static.ts` is unassigned in the plan and belongs to Lane A); the browser job therefore proves the runner, the audit and the loopback API, not a rendered screen.
- **Repository script tests live in `scripts/*.test.mjs`**, run by `node --test scripts/*.test.mjs` in the `demo-and-frozen-source` job and listed in `TESTING.md`. They are neither the demo suite (root `tests/`, untouched) nor the product suite (`rai-web`), which keeps the plan's "the demo suite and the product suite never share a command".
- **`SessionInfo['identityMode']` is `never`** in `rai-web/shared/src/schemas/auth.ts` (`Type.Union(IDENTITY_MODES.map(...))` loses the tuple), so a `SessionInfo` literal cannot be written in TypeScript. This ticket avoided it (`asUser` takes only the cookie); W1-01a will hit it when its route returns `SessionInfo` and should fix it in the shared contract (a contract PR, Lane A). Recorded here rather than fixed, because `shared/` is not this ticket's module.
- **The link check also verifies heading anchors**, which is stricter than "relative links resolve"; the whole repository passes today, and the checker follows the GitHub slug rule (tested). If a future document needs an anchor form the rule misses, the fix goes into the script, not into skipping the check.
- **Actions are pinned by major tag** (`actions/checkout@v4`, `actions/setup-node@v4`, `actions/upload-artifact@v4`); pinning to commit SHAs is a lead choice not made here.
- No dependency was added or bumped; `package-lock.json` is unchanged.

Not edited, on purpose: `docs/product/source-spec.md` (frozen; hash unchanged), `docs/product/decisions.md` (no decision; D07-D10 untouched), `docs/board/*`, `DEVLOG.md`, `CHANGELOG.md` (appended by the merge step), `docs/architecture/README.md` (its "Path in repo" column has no CI row; the plan's 1.1 table owns that mapping), `rai-web/package.json` (every command this ticket needs already exists from W1-00; `fixtures:*` belong to W1-09), `rai-web/server/**`, `rai-web/web/**`, `rai-web/fixtures/**`, `demo/`, root `tests/`.
