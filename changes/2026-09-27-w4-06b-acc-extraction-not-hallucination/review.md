## Change

- **`ACC-EXTRACTION-NOT-HALLUCINATION`** (`server/src/qc/content/rules/acc-extraction-not-hallucination.ts`): approve attempts only. A claim on the hallucination item whose `metric` (as a metric ID) is in `params.extractionMetrics` is a finding: one per claim, artifact scope, `claimKey`, evidence = locator plus `excerptHash` (identical claim text merged, one evidence entry per occurrence), `measure` = the stated figure under the cited metric ID, message `qc.finding.acc_extraction_not_hallucination` `{ slot, metric, item? }`.
- **`ACC-CLASSIC-ML-METRIC`** (`rules/acc-classic-ml-metric.ts`): approve attempts only. An attached artifact passes when a `classic_ml_performance` claim cites a metric in `params.matchingMetrics` with a parseable value, or answers N/A with a reason (non-empty `evidence`). Otherwise one artifact finding (no `claimKey`), evidence = every performance claim (locator plus `excerptHash`) or one `absent` locator, `measure` null, message `qc.finding.acc_classic_ml_metric` `{ slot, threshold_source }`.

Label stays `w4a.1`.
- **Documents**: W0-07 3.5 dated W4-06b note (the two rule rows) in `qc-boundary-and-mail-sink.md`.
- **Tests**: new `rules/acc-extraction-not-hallucination.test.ts` (8) and `rules/acc-classic-ml-metric.test.ts` (8); new cases in `configuration/{seed,qc-rules}.test.ts`; `fixtures/src/evaluation/content-rules.test.ts` now compares every implemented content rule (and so the `classic_ml` cases) against the dev-split labels; a comment in `runner.test.ts` updated (the seeded `llm` selection is still refused until W4-06c).

## Deviations

- **Extraction rule fires whatever the answer.** The ticket row says "extraction-only 'Yes' flagged"; the plan's rule table says a claim on the hallucination item that cites an extraction metric. Followed the table (the plan's rule is the stricter superset): a "No" or N/A that offers an extraction figure for hallucination is flagged too. Tested.
- **Extraction `measure` when no value is stated.** The plan says `measure.metric = 'extraction_accuracy'` (W0-07 3.5: measure required), and `MeasureSchema` needs a unit. Chosen: the measure is always present with the cited metric ID (the seed lists only `extraction_accuracy`), value/denominator/threshold null when not stated as numbers, unit from the value, else the stated `unit` word, else `percent`. The alternative (null, as `ACC-METRIC-CITED` does) would drop a measure the plan and W0-07 require.
- **Classic-ML finding granularity.** The rule's condition is about the whole artifact ("no claim ... and no N/A with a reason"), so it raises one finding per artifact without `claimKey` (decision 30's claim discriminator is for per-claim defects); the evidence lists every performance claim, or `absent`. At most one artifact (slot 1) is read per run, so no key can collide. Matches the W4-09a labels (`ev-dev-09`, `ev-dev-11`).
- **"A reason" for an N/A answer** is the claim's `evidence` field, non-empty after trimming: the grammar has no reason key, and the W4-09a dev documents write the N/A reason there (`ev-dev-10`). Adding a `reason` column key would change `ClaimLabelsSchema` for every published revision.
- **Classic-ML `measure` is null**: the plan names no measure for this rule, and there is no matching figure to report. The substitute script's classic-ML measure is a fixture shape (W0-07 3.5 first table), untouched.
- **Metric lists (WA-D09, provisional):** `extractionMetrics ['extraction_accuracy']` (the dev vocabulary's only extraction metric); `matchingMetrics ['f1', 'precision', 'recall', 'auc_roc', 'accuracy']` (the dev vocabulary's `f1` plus the usual classification metrics; D09 owners retune per sheet). Item keywords: `hallucination` / `การหลอน` (as `ACC-METRIC-CITED`) and `model performance` / `ประสิทธิภาพของโมเดล` (the dev vocabulary).
- **Paths outside the row's list** (test-only): `fixtures/src/evaluation/content-rules.test.ts` (W4-06a's dev-split cross-check, extended; labels unchanged) and `server/src/qc/content/runner.test.ts` (one comment). `server/src/qc/content/claims.ts` gains the exported helper `statedUnitOf` so the extraction rule does not duplicate the unit word table. No locale key was needed: both message keys already exist in th and en with the params used.
- **No changed expectation** in any existing test.
- **Lane environment**: `RAI_PG_TOOLS=docker-compose:rai-qc-content` in the uncommitted `.env` (the first integration run used `.env.example`'s `rai-dev` and the six W7 backup/restore tests failed with `pg_tools_container_not_found`; fixed by the env value, no code change).
