## Notes for the reviewer (HRR)

- **`configuration_revision_id` in slice 1.** W0-04 says the FK column holds the `qc_rules` revision and the jsonb every kind. No `qc_rules` revision exists on `main` (W1-10 is not merged; the seed publishes five kinds). The freeze therefore records the `qc_rules` revision when one is in force and otherwise the W0-02 7.3 `ConfigurationView.revisionId` value (the latest published among `use_case_groups`, `checklist_templates`, `sla`, with the same tie-break as `effectiveConfiguration`), so the frozen id equals what `GET /api/configuration/current` showed the submitter and what the W1-13 substitute serves. `frozen_configuration` always carries every kind. Unit-tested in `freeze.test.ts` for both branches. No spec was changed; this is the reconciliation of the two documents for the period before W1-10 publishes `qc_rules`.
- **`row_version` after submit.** The case counter advances by one on submit (W0-04 `case.row_version`: "every update"); `CaseView.caseRevision` reflects it. The submitted version's own reference is its id; `ExpectedVersion.revision` for submitted-version actions is a consistency check only (W0-06 5.1).
- **Resubmit.** A draft with `parent_version_id` set cannot exist before W2-03; the same transaction is the base for W2-04, which adds `version.resubmitted` and `ai_readiness_status = 'not_ready'`.
- **W2-01's (d)-(f)** (lane opening, outbox rows, SLA clock) and pack QC after commit (W0-07 3.4) are not here, as W0-06 4.3's Tickets row says for W1-05.
