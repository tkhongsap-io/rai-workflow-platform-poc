# Intent: rubric schema and pure scoring engine (W5-01, #204)

W5 proposes a risk tier for each submitted version from a seven-question questionnaire. Before anything can be stored, seeded or shown, the desk needs two things every later W5 ticket builds on: a schema that says what a `risk_rubric` configuration body may contain, and a scoring engine that turns a set of answers into a tier with its explanation. This ticket adds both, and nothing else.

The engine is pure and lives in `rai-web/shared`, with no Node or DOM import, so the server (at submit, W5-05) and the browser (the pack editor's live preview, W5-07) run exactly the same code. Missing evidence never becomes Low: an unanswered question, an explicit "Unknown", an answer whose evidence slot is not attached, or an answer that names an option the rubric does not have is Unknown with its reason, and the engine computes the exact range of tiers the Unknown questions could still produce. When that range is a single tier the tier is determinate; otherwise it is `unknown` with its bounds.

It is the first W5 implementation ticket (order 1 in section 9 of the [W5 plan](../../docs/engineering/implementation-plan-w5.md)) and implements section 3 under the register rows "Ta's delegation (2026-09-27)" and "W5 delegated rulings (provisional)" (R-2, R-5, R-6, R-7, R-9, R-13). The schema is not registered as a configuration kind (W5-02), no placeholder is seeded (W5-02) and nothing is stored, routed or shown (W5-03 onwards). D07 (the questionnaire's content, thresholds and labels) stays open for AI/COE: the operating-model section 7 summary appears only in a unit test labelled "expressiveness only, not the approved rubric". Synthetic data only; no network call; no deploy.
