# Intent: deterministic runner for metadata rules (W4-03, #186)

W4-02 put a rule catalogue on every new version and made the orchestrator send the runner the rules that apply (`request.rules`). No runner executes them yet: the only runner is the scripted substitute, which replays fixture scripts. W4a needs a real product runner that reads only structured pack data, so that the desk can raise the provisional W4a findings on any case, not only on scripted fixtures.

This ticket adds the `deterministic` runner under `server/src/qc/deterministic/`. It implements the `QcRunner` port and executes the three W4a metadata rules as pure functions of the request: `PACK-SLOT-MISSING` (single-lane slots on submit; slot 5 per lane on approve attempts), `PACK-STAGE-MISMATCH` and the new `PACK-NA-VENDOR-DOC`. It answers a request with no rules (`rules: null`) with `unavailable:not_configured`, never a clean pass, and counts only the rules it executed. Tests show it never reads document bytes and imports no parser and no network module. It is the third W4a ticket (plan section 9, order 3) and implements [W4a plan](../../docs/engineering/implementation-plan-w4a.md) section 4 under the register rows "W4a gate entry", "D05 refinement (upload slot 5 and 9)" and "W4a kickoff rulings" (Ta, 2026-09-26).

Not here: binding the runner at start (`QC_MODE`, W4-13, which also adds the real-server test), the upload trigger (W4-04), the QC log UI (W4-12), finding dedup (W0-07 3.4 step 6, moved to W4b), content rules (W4b). No suite that binds the scripted substitute changes behaviour. Rule outcomes are provisional until D09. Synthetic data only; no document parsing, model, provider or network call.
