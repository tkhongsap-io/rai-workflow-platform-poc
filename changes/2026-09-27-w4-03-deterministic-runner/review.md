# Review: deterministic runner for metadata rules (W4-03, #186)

Framed in [intent](intent.md), [spec](spec.md) and [plan](plan.md). Source: [W4a plan](../../docs/engineering/implementation-plan-w4a.md) section 4, with the plan-review notes on the ticket. Decisions implemented: register rows "W4a gate entry", "D05 refinement (upload slot 5 and 9)" and "W4a kickoff rulings" (Ta, 2026-09-26). Synthetic data only; no document parsing, model, provider or network call. Rule outcomes are provisional until D09.

## Change

- **Runner** (`server/src/qc/deterministic/runner.ts`): `createDeterministicQcRunner({ now?, runnerVersion? })` implements the `QcRunner` port with identity `{ runner: 'deterministic', runnerVersion }`. The default version is the `@rai/server` package version, read once by the new `server/src/server-version.ts` (the same relative path resolves from `src/` and `dist/`). `qcKindOf` (W4-11a) already maps it to `deterministic`.
  - `rules: null` → `unavailable:not_configured`, detail `no_qc_rules_revision`.
  - `content` rules are skipped and not counted; each `metadata` rule runs in request order and is listed in `rulesEvaluated`.
  - `runner_error` (named detail) for a metadata rule it does not implement (`unknown_metadata_rule`), a rule selected on a trigger it is not defined for (`unsupported_rule_trigger`), params that fail the rule's schema (`invalid_rule_params`), an unknown lane mapping (`unknown_lane_mapping`) and an approve attempt without a lane (`approve_attempt_without_lane`).
  - One timestamp for `startedAt` and `finishedAt`; no store, no clock but `now`, never `read()`.
- **Rules** (`server/src/qc/deterministic/rules/`), each a pure function of the request and its catalogue entry, with the triggers it is defined for; `rule.ts` holds the shared finding builder (`findingKeyOf`, the request's revision and trigger, the catalogue severity, `measure: null`, provenance) and the slot evidence (locator `absent`, plus the artifact reference of an attached slot):
  - `pack-slot-missing.ts`: submit, each `missing` single-lane slot (1-4, 6-8 under `lane-mapping/v1`) owned by its lane; approve attempt, each `missing` multi-lane slot that the run's lane reviews (slot 5) owned by the run's lane. Lanes come from `owningLaneRule` over the version's recorded mapping.
  - `pack-stage-mismatch.ts`: submit; `params` checked against `StageMismatchParamsSchema`; one AI/COE pack finding with one evidence entry per offending slot (slot 9 excluded).
  - `pack-na-vendor-doc.ts`: submit; on a vendor case each of `VENDOR_SLOTS` (3, 4) that is `not_applicable`, any reason, owned by its lane (DPO).
  - `index.ts`: the registry by rule ID.
- **Locales** (th, en): `qc.finding.pack_na_vendor_doc { slot }`, and `qc.rule.<rule_id>` labels for the seven catalogued rules and `QC-UNAVAILABLE`.
- **Test-environment binding (round 2)**: `config.ts` `parseQcMode` accepts `QC_MODE=deterministic` only under `NODE_ENV=test` (any other environment: `invalid:QC_MODE`, exit 78); `start.ts` binds `createDeterministicQcRunner` for it, with a probe that answers `ok` (in-process, no store), and readiness reports `qc.kind` from the bound runner's identity (`qcKindOf`) instead of the constant `substitute`. The `substitute` path, the production non-binding and the test override are unchanged.
- **Docs**: W0-07 (`qc-boundary-and-mail-sink.md`) gains two dated W4-03 amendments: after 3.4, step 6 dedup deferred to W4b (its scope key must include the owning lane for slot 5); after 3.5, the W4a rule rows including `PACK-NA-VENDOR-DOC`.
- **Tests**:
  - `server/src/qc/deterministic/rules.test.ts` (16): below/at/above fixtures for each rule; `PACK-STAGE-MISMATCH` every stage against slot 8 attached and against each of slots 1-9 not yet; the unit-level two-lane slot-5 case; no slot-9 defect over every state, stage, trigger and lane; severity from the catalogue; the locale keys. Every finding is checked with `validateQcFinding` and `checkOwningLane` unchanged.
  - `server/src/qc/deterministic/runner.test.ts` (7): identity and version; `null` rules; `[]` rules; `rulesEvaluated` with content rules; each `runner_error`; the never-`read()` test (artifacts whose `read()` rejects, a read counter at 0 after runs that raise every rule); schema-valid, repeatable output.
  - `server/src/qc/deterministic/module-graph.test.ts` (2): the transitive static import graph of the non-test modules under `server/src/qc/deterministic/` reaches no network module (`node:net`, `node:http`, `https`, `http2`, `tls`, `dgram`, `dns`, `undici`, `openid-client`), no document parser (a named list), no `pg` or `drizzle-orm`, no module under `server/src/artifacts/` or `server/src/db/`, and no dynamic import; its only built-ins are `fs` and `url` (the package-version read). A second test shows the walker does detect a forbidden import.
  - `server/src/qc/deterministic/request-builder.test-helper.ts`: the synthetic request of the unit tests.
  - `tests/integration/w4-03-deterministic-runner.test.ts` (6), real Postgres, fixture app with the runner injected: submit findings for each rule (`fx-case-missing-slot`, `fx-case-nonvendor` at `idea`, `fx-case-vendor` with slot 6 not yet, `fx-case-na-reasons`); the two-lane slot-5 case over HTTP (lane QC runs by DPO and IT/Security, cross-lane waivers 403, own-lane waivers 201); replay of completed submit and approve-attempt runs; `rules: null` answered `not_configured` by the runner itself (engine `deterministic`, retried, one QC-UNAVAILABLE finding owned by the lane); `rules_evaluated` 3 on submit and 1 on approve attempts; `runner_version` equals the server package version; `qcKind` `deterministic` on `qc.run.started`.

## Deviations

- **`QC_MODE=deterministic` introduced for the test environment only (round 2).** Round 1 had moved the real-server test to W4-13 without recorded authority (review round 1, blocking). It is now in this ticket as plan sections 8-10 and issue #186 require, using the route the issue names: the value is introduced "via the test env only" because W4-13 has not landed. `config.ts` refuses it outside `NODE_ENV=test`; `.env.example`, CI, the default, the production refusal of `substitute`, W0-02 section 5 and TESTING stay W4-13's (plan section 12). Readiness `qc.kind` now comes from the bound runner's identity, which W4-13 would otherwise have added in `health.ts`/`start.ts`; for every existing configuration it still reports `substitute`.
- **The qc-runs endpoint is not read by the real-server test.** Plan section 8 lists it, but it does not exist until W4-12 (plan section 9 row 6); the test reads the `qc_run` rows from the database instead, and W4-12 extends the file with the endpoint.
- **One rules test file.** plan.md named three per-rule test files; they were written as one `server/src/qc/deterministic/rules.test.ts` with the same cases (below/at/above per rule, slot 9, owning lanes, the unit two-lane case).
- **Evidence of a stage mismatch.** The plan gives the scope (pack) but not the evidence. The finding carries one evidence entry per offending slot, in slot order, locator `absent` (the rule reads a slot state, not a place in a document), with the artifact ID and content hash when the offending slot is attached. The message stays `qc.finding.pack_stage_mismatch` with no params, as the substitute scripts already use it.
- **Fail closed where the plan is silent.** A metadata rule ID the runner does not implement, a rule selected on a trigger its definition does not cover (for example a catalogue listing `PACK-SLOT-MISSING` for `upload`), invalid `params`, an unknown lane mapping and an approve attempt without a lane each make the run `unavailable:runner_error` with a named detail. The plan says only that an outage is never a clean pass; silently skipping would give a shorter result that reads as clean. Stored catalogues are validated on write (W4-02), and the seed triggers match the rule definitions, so none of these fire on the fixture set.
- **Approve-attempt scope of `PACK-SLOT-MISSING`.** Implemented as "a `missing` slot reviewed by several lanes that include the run's lane", which is slot 5 under `lane-mapping/v1` (the only multi-lane slot). A single-lane slot is not raised again on approve attempts; the plan's table lists only slot 5 for that trigger.
- **Rule label keys.** The plan asks for one label key per rule ID for the QC log. Added for the seven rule IDs of the `w4a.1` catalogue (the W4b content rules included, because W4-12's QC log shows the substitute's `ACC-*` findings under the evidence configuration) and for `QC-UNAVAILABLE`, as `qc.rule.<rule_id>`. W4-12 consumes them.
- **`finishedAt` equals `startedAt`.** The rules are synchronous and pure; one clock read keeps the output repeatable for a given `now`.
- **No existing test changed.** No existing expectation needed to change: the substitute is still what every existing suite binds. Round 2 edits only the header comment of `w4-03-deterministic-runner.test.ts` to point at the real-server test.

## Deferred reviewer notes (round 1, non-blocking)

- `server-version.ts` reads `../package.json` at module load and throws if it is missing: W4-13 packaging and start must keep `server/package.json` next to `src/` and `dist/`.
- The runner ignores the abort signal; it is synchronous, and the orchestrator's timeout and catch still fail closed.
- `freezeWithoutQcRules` in the integration test toggles the `pack_version_frozen` trigger inside one transaction; it relies on the one-suite-per-Postgres rule.
- `approve_attempt_without_lane` is raised before any rule runs, even when every selected rule is a content rule: stricter than needed, fails closed, kept.
- Two lanes' slot-5 findings share one `findingKey` on one version; safe today (no unique index on it). The W4b dedup key must include the owning lane, as the W0-07 3.4 amendment records.
- No seeded metadata rule has the `upload` trigger; W4-04 must keep that, because the runner answers `runner_error` for a rule selected on a trigger it does not support.
