## Plan

1. `server/src/artifacts/blob-store.ts`: the W0-04 `BlobStore` interface plus a staged write (`stage` → temp file under `BLOB_DIR/tmp/` hashed while streaming with the per-file cap; `commit` → fsync, atomic rename into `sha256/<h[0:2]>/<h[2:4]>/<h>`, dedupe with size check; `discard`), `open`, `exists`, `verify`; `FilesystemBlobStore` creates the root `0700`, files `0600`, and empties `tmp/` at start. A `put` composes stage and commit for callers that need no inspection (the fixture loader).
2. `server/src/artifacts/filename.ts`: the W0-08 section 3 filename rule (NFC, ≤ 200 code points, no path or control characters, no leading/trailing whitespace, not `.`/`..`, allowed extension with a non-empty stem) and the RFC 8187 `Content-Disposition` builder with the ASCII fallback.
3. `server/src/artifacts/sniff.ts`: pure, Node built-ins only: magic on the first 8 KiB, kind versus declared extension, structural checks (PDF `%%EOF` and active-content scan; ZIP EOCD/polyglot, ZIP64, entry caps, methods, encryption, names, `vbaProject.bin`, nested archives, package kind; PNG `IHDR`/pixel cap/`IEND` last; JPEG SOF walk/pixel cap/`FF D9` last) → `{ ok, kind, mediaType } | { ok: false, reason }`.
4. `server/src/artifacts/pipeline.ts`: W0-08 section 4 checks 3-12 in order (open draft before any byte; filename; stage with the cap; empty; sniff; structure; per-pack total under the case lock; blob commit; artifact row and `artifact.uploaded` in one transaction); `upload.rejected` / `upload.stored` lines; the rejected filename and bytes are never logged or stored.
5. `server/src/artifacts/routes.ts`: `POST /api/cases/:caseId/artifacts` (multipart, one `file` part, `limits.files 1`, `limits.fields 0`, `throwFileSizeLimit`), `GET /api/artifacts/:artifactId` (bytes with the W0-08 section 6 headers, audit `artifact.downloaded`) and `/meta`, each declaring its `config.auth` (`artifact.upload` on `:caseId`, `artifact.download` on `:artifactId`); multipart limit errors mapped to `unsafe_upload too_large` and `invalid_input`.
6. `app.ts` registers the routes when `deps.artifacts` is given; `start.ts` builds the filesystem store from `BLOB_DIR`; `config.ts` refuses an `UPLOAD_MAX_*` value above the W0-08 default in `local-google` and `fixture` modes (W0-02 section 5 row); `operator/store-verify.ts` and `store-cleanup.ts` use the store; the fixture loader's one blob-write call site moves to `BlobStore.put` (the W1-09 review declares that hand-over).
7. Tests first where the clause is testable. Unit: filename rule and disposition header; the section 8.6 hostile rows that are pure bytes against the sniff; the filesystem store (temp, rename, dedupe, cap, modes, verify). Integration (`tests/integration/w1-03-*.test.ts`, real Postgres, fixture set loaded, `app.inject`): every Done-when clause, T10/T11/T12/T33 for `artifact.*`, no open draft, no `file` part, the hostile rows through the route including the 25 MiB boundary and the 150 MiB pack total, dedupe of identical bytes, the audit and log shapes.
8. Docs: TESTING.md (routes and the two store commands), this folder's review.md. No migration: the `artifact` table, its trigger and the `rai_app` grants exist since 0000, so the journal is untouched.
