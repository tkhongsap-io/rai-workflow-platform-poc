# Intent: real, revocable artifact read handles in the QC request (W4-05a, #211)

A QC run request lists the artifacts the runner may look at, each with a `read()` handle. Since W2-05 that handle has been a placeholder: `read()` returned an empty stream, whatever the artifact held. That was harmless while every runner looked only at metadata (the scripted substitute and the W4a `deterministic` runner never call `read()`), but W4b brings a content runner that must read the stored bytes of slots 1, 2 and 5 to check claims (W4b plan sections 3 and 4). An empty stream there would read as an empty document and, worse, could let a content rule pass on nothing.

This ticket makes the handle real and bounded in time. `read()` streams exactly the stored bytes of that artifact from the blob store, the same store the authorized download route reads. It works only while the run is in progress: the orchestrator revokes every handle once the runner settles or the deadline fires, so a runner that keeps a handle cannot read after its run ended. When the store is not bound, or the blob is missing, `read()` rejects instead of pretending the document is empty; the content runner (W4-06a) maps that rejection to an `artifact_unreadable` outage, never a clean pass.

It is W4b ticket 4 (serial track T1, after W4-11b) and implements [W4b plan](../../docs/engineering/implementation-plan-w4b.md) section 4.1 and section 15 row W4-05a under the register rows "Ta's delegation (2026-09-27)" and "W4b delegated rulings (provisional)". D07-D10 stay open. No migration, no rule, no model, no network call; the existing runners are unchanged; synthetic data only.
