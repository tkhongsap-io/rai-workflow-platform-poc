# Specification

Source: the W4-05b row of section 15 of the [W4b plan](../../docs/engineering/implementation-plan-w4b.md), section 4.2 (port and worker), section 4.4 (limits), decisions 5 and 23, the unit layer of section 13, and [ADR-0006](../../adr/0006-qc-engine-and-extraction.md) (provisional). The plan wins over issue #212. No spec amendment is assigned to W4-05b.

Done when:

1. **Port** (`server/src/qc/extraction/port.ts`): `Locator` (the shared `EvidenceLocator`, so W4-16's text-free shape follows automatically), `Segment { locator, text }`, `ExtractResult` (`ok: true` with `extractorVersion` and `segments`, or `ok: false` with `extractorVersion` and one of `unreadable | limit_bytes | limit_time | limit_memory | limit_output | crash`), `Extractor { version; extract(input, signal); selfTest() }`, exactly as the plan's section 4.2 block.
2. **Limits** (`limits.ts`): the configurable limits `timeoutMs` (500-9000), `maxMemoryMb` (64-512), `maxTextChars` (1000-2 000 000), `maxConcurrency` (1-4) and `maxInputBytes` (at least 1; W4-13b passes the upload cap) with their policy bounds exported for W4-13b; the fixed section 4.4 limits (50 000 segments, 20 MiB per decompressed part, 100 MiB per artifact, 2 000 PDF pages, 100 000 PDF objects). Out-of-bounds limits make `createWorkerExtractor` throw; there is no default.
3. **Protocol** (`protocol.ts`): one request (`{ mediaType, bytes, limits }`, where `limits` are what the worker enforces itself) and one reply. The reply is checked against a TypeBox schema: `{ ok: true, segments: [{ locator, text }] }` or `{ ok: false, reason: unreadable | limit_bytes | limit_output }`, no other key. A reply over `maxTextChars` characters or 50 000 segments is `limit_output`; any other malformed reply is `crash`. The extractor version is stamped by the host, never taken from the worker.
   - Note (2026-09-27, round 1): "no other key" holds inside each locator too. The reply's locators are checked against a strict wire schema (the five shared kinds, every variant and the page region closed to extra keys, each `sheet`, `cell` and `heading` at most 512 characters), and locator strings count toward `maxTextChars` in both the worker's sink and the host's recount; a locator string over the bound is `limit_output`.
4. **Host** (`client.ts`, `createWorkerExtractor(limits, options?)`):
   - one `child_process.fork` per `extract` call (one process per call; two calls never share a PID), `env: {}`, `serialization: 'advanced'`, `stdio: ['ignore', 'ignore', 'ignore', 'ipc']`;
   - `execArgv`: the parent's loader flags (`--import`, `--require`, `--loader`, `--conditions`) only when the entry is TypeScript, plus `--max-old-space-size=<maxMemoryMb>`, plus the permission flags of item 7;
   - the entry is `worker/main.ts` when the host runs from source and `worker/main.js` when it runs from the build;
   - input over `maxInputBytes` → `limit_bytes` with no fork; an already aborted signal → `limit_time` with no fork;
   - the wall clock (`timeoutMs`, from fork) or an abort → SIGKILL and `limit_time`; an over-cap reply → SIGKILL and `limit_output`; a heap death (SIGABRT or exit code 134) → `limit_memory`; any other exit before a reply, a spawn or send error, or a malformed reply → `crash`;
   - the worker is SIGKILLed once its reply is read, so no worker outlives its call;
   - a FIFO semaphore of `maxConcurrency` counts live processes (a slot frees when the process has exited); a queued call whose signal aborts leaves the queue with `limit_time` and never forks;
   - `version` is `rai-extract/1+<server package version>`;
   - `selfTest()` resolves `true` when a worker round-trips a probe and answers with a well-formed reply, `false` otherwise (W4-05c tightens it to the embedded synthetic DOCX; W4-13b binds it to readiness).
5. **Worker** (`worker/main.ts` entry, `worker/extract.ts` dispatch): reads one message, answers with one reply. Formats are a registry keyed by media type, empty in W4-05b (every input is `unreadable`), where W4-05c and W4-05d register DOCX, XLSX and PDF. A segment sink enforces `maxTextChars` and `maxSegments` (`limit_output`); a parser signals `unreadable`, `limit_bytes` or `limit_output` by throwing a typed stop; any other throw kills the worker (`crash`). No segment means `unreadable`.
6. **Module graph** (`worker/module-graph.test.ts`): every non-test module under `worker/` imports only `node:zlib`, `node:buffer` and files under `worker/`; no dynamic import, no `require(`; the check sees a forbidden import when there is one.
7. **Permission flags**: Node 24 `--permission` is added to the fork if it works under both layouts, with the narrowest `--allow-fs-read` each layout allows; otherwise review.md records why not. If added, a test shows the worker cannot write a file or spawn a process.
8. **Fork latency**: a unit test, run in CI's unit job, measures fork-to-reply for the worst W4b case (two extractions at concurrency 2) under the source layout (`tsx`) and under a precompiled JavaScript worker, and asserts both stay under half the 10 000 ms deadline and each under 4000 ms; review.md records the numbers, plus a measurement against the real `npm run build` output. If the source layout left less than half the deadline, the source layout would fork a precompiled entry (plan section 4.2).
9. Nothing extracted is logged, stored or cached (decision 23): the host has no logger and keeps no state between calls. No config key, runner, orchestrator change or migration. Full plan gate green.
