# Specification

Source: W4b plan section 15 row W4-11b, sections 7, 8 and 9 (the plan wins over issue #201).

Done when:

1. **Migration `00NN_w4_11b_run_extraction_identity`** (forward-only, number taken on current `main`: 0014 (was 0010, then 0011, then 0012, then 0013, before W5-03 merged `0010_w5_03_risk`, W7-03 merged `0011_w7_03_migration_class` and W6-02 merged `0012_w6_02_configuration_admin` first; regenerated by hand at each rebase); rollback class `additive`, entered in W7-03's `MIGRATION_CLASSES`) adds to `qc_run`, all nullable and NULL on earlier rows:
   - `extractor_version text`, `model_provider text`, `model_id text`, `prompt_revision text`;
   - `model_input_tokens integer`, `model_output_tokens integer`, `model_latency_ms integer`, `model_cost_usd_micros bigint`, each with `CHECK (col IS NULL OR col >= 0)`;
   - `unavailable_detail text` with `CHECK (unavailable_detail IS NULL OR (status = 'unavailable' AND unavailable_detail ~ '^[a-z0-9_]{1,64}$'))`.
   - No trigger or grant change (adding nullable columns fires no UPDATE trigger; the `rai_app` INSERT/SELECT grant on `qc_run` covers them). It applies on a W4a (0009) database with rows in it.
2. **`QcRunResult.engine?`** (`shared/src/qc/types.ts`) on both statuses: `{ extractorVersion?: string; model?: { provider: 'local-fake'; modelId; promptRevision; inputTokens; outputTokens; latencyMs; costUsdMicros } }`. `QcEngineIdentitySchema` (`shared/src/qc/validate.ts`) bounds it: identifiers only (`^[A-Za-z0-9][A-Za-z0-9._+/@:-]{0,127}$`), no provider value but `local-fake`, non-negative integers (int32 for tokens and latency, safe integer for cost), no unknown key; `QcRunResultSchema` accepts it on both statuses.
3. **Boundary check** (`qc/orchestrator.ts` `checkedResult`): an `engine` that fails the schema makes the run `unavailable:runner_error` with detail `engine_identity_invalid` and no identity recorded. A valid `engine` is kept when a finding violation turns the result into `runner_error`.
4. **`recordRun`** writes the columns from the (checked) result: extractor and model columns when present, NULL otherwise (unbound, timeout, thrown error, runners without extraction or model use). `unavailable_detail`: the result's `detail` when it matches `^[a-z0-9_]{1,64}$`; `unspecified` when a detail is given that does not; NULL when the detail is null or the run completed. Selection details (`unknown_template_version`, `invalid_rule_catalogue`), deterministic runner details and validator violations are therefore now persisted.
5. **Logs** (W0-10 catalogue and W0-07 section 7 amended, dated): `qc.run.completed` and `qc.run.unavailable` gain `extractorVersion`, `modelProvider`, `modelId`, `promptRevision`, `modelInputTokens`, `modelOutputTokens`, `modelLatencyMs` (present only when recorded); `qc.run.unavailable` also `unavailableDetail` (the stored value, when not NULL). `qc.extract.failed` is registered with `qcRunId`, `slot`, `reason`, `durationMs`, `extractorVersion` for W4-05b/W4-13b to emit. `alreadyRecordedCount` (W4-15) and `qc.model.call` (W4-07b) are not added here. No filename, document text, excerpt, model input or output, or message param.
6. **qc-runs read** (`QcRunSummarySchema`, `listQcRunsForVersion`): `extractorVersion: string | null`, `model: { provider, modelId, promptRevision } | null`, `modelUsage: { inputTokens, outputTokens, latencyMs } | null`, `unavailableDetail: string | null`. Authorization unchanged. The cost is not served.
7. **Operator report:** each `DeskHealthReport.unavailableQc` row gains required `unavailableDetail: string | null` (the stored detail, bounded by the same pattern plus `unspecified`).
8. **Distinguishable:** two runs on one version that differ only in extractor version, model identity or prompt revision are told apart from their rows and log lines alone.
9. Documents amended with dated notes: W0-02 section 7 (read shape), W0-04 persistence document and the data contract (columns), W0-07 section 7 (logs), W0-10 catalogue.
