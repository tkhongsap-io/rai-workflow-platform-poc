# Intent: run identity for extraction and model use; `unavailable_detail` (W4-11b, #201)

W4b makes QC read document contents: an extraction worker (W4-05b-d) and, disabled by default, a model port with a local fake (W4-07a-b). A `qc_run` row today names only the runner, its version and the rule revision (W4-11a), and an unavailable run keeps its reason but drops the runner's `detail` (the W4a note "selection detail not persisted"). Two runs on one version that differ only in the extractor build, the model or the prompt revision could not be told apart from rows and logs alone, and an operator could not see why a run was unavailable beyond its four-value reason.

This ticket adds the identity and usage columns for extraction and model use and `unavailable_detail` to `qc_run` (one additive migration), an optional `engine` block on `QcRunResult`, validated at the orchestrator boundary and written by `recordRun`, the matching fields on `qc.run.completed` / `qc.run.unavailable`, the qc-runs read shape and the operator report's unavailable rows. It is W4b ticket 3 (serial track T1, first on the orchestrator and migration chain) and implements [W4b plan](../../docs/engineering/implementation-plan-w4b.md) sections 7 (W4-11b row), 8 and 9 (`QcRunSummary`) under the register rows "Ta's delegation (2026-09-27)" and "W4b delegated rulings (provisional)". D08 and D09 stay open. No extractor, model, rule or UI is added; nothing leaves the machine. Synthetic data only.
