# Intent: Admin configuration API (W6-04, #231)

W6-02 gave the store Admin drafts, publish with a change note and restore; W6-03 added the cross-kind and registry checks those Admin paths run. Nothing serves them yet: an Admin still cannot change a checklist template list, a QC catalogue, the SLA days, the calendar or any other Admin-owned kind without a code change or a direct database write.

This ticket serves the store over HTTP under `/api/admin/configuration`, exactly as the [W6 plan](../../docs/engineering/implementation-plan-w6.md) section 4.2 and row W6-04 fix: the index of every kind with its current revision and draft, the revision history (newest first, with change notes and how many submitted versions froze each revision), a revision's body, the draft with the problems publish would refuse today, and the four writes (save draft, discard draft, publish, restore). Reads need `config.read_revisions` and writes `config.publish`; both are Admin only (W0-05, T40). Every refusal uses the W0-06 contract: 404 `configuration` for a kind or revision that does not exist, 409 `stale_version` `configuration_changed` when the draft or the revision in force moved, and 422 `invalid_input` with each problem as a field path and a th/en locale key. Publishing and restoring log `configuration.published` or `configuration.publish_refused` (W6 plan section 10) and audit through the store.

It serves the north star (Ta, 2026-09-27): configuration becomes editable, versioned and audited without a redeploy, and the Admin screens (W6-05 to W6-07) and the activation proof (W6-08) can build on it. Register rows "Ta's delegation (2026-09-27)" and "W6 delegated rulings (provisional)" apply (Q1 drafts, Q3 restore, Q4 single-Admin publish, Q5 optimistic checks, Q18 draft validity). D07, D09 and D10 stay open; their kinds are editable and carry their values owner in the index. No migration, no UI, no desk-controls enforcement (W6-17). Synthetic data only; no network call; no deploy.
