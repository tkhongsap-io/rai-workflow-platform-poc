## Deviations, defaults and limitations (for the reviewer)

- **Error `messageKey` on refused sign-ins.** W0-03 section 6.4 lists `auth.session_required`, `auth.sign_in_failed` and `auth.not_permitted` as the `messageKey`, while W0-06 8.2 (which W0-02 7.1 marks authoritative for the envelope, and which the merged `shared/src/errors.ts` types as `error.${code}`) fixes `messageKey` to `error.unauthenticated` / `error.forbidden`. The server sends the W0-06 envelope. The `auth.*` keys exist in both catalogues for the sign-in screen (W1-07) to render by route: a failed `GET /auth/callback` → `auth.sign_in_failed`, a 401 from `GET /api/session` → `auth.session_required`, a 403 from the callback → `auth.not_permitted`. If the lead prefers the `auth.*` keys in the body, that is a W0-06 8.2 amendment first.
- **Session sweep runs as the operator, not inside the process.** W0-03 6.3 says expired and revoked rows are deleted by `reset` and "a periodic sweep (W1-01)". W0-04 gives `rai_app` no DELETE anywhere, so the sweep is `sweepSessions()` inside `npm run db:cleanup` (rai_operator) rather than a timer in the Fastify process. Expired and revoked rows are inert (they never authenticate); nothing depends on their removal.
- **S12 applies to `production` as the table states.** `network`/`ad` with no published mapping starts and refuses every login with `no_mapped_group` (the resolver has no rules); an invalid or other-tenant mapping refuses to start in both modes.
- **`set-locally` counts as absent (S15).** The table names `set-in-custody`; the sample client-id placeholder `set-locally` is treated the same way so a copied `.env.example` refuses to start with `secret_missing:RAI_IDENTITY_GOOGLE_CLIENT_ID` instead of sending a placeholder to Google.
- **Fixture identities at run time.** The built server in fixture mode loads `@rai/fixtures/data/users` by dynamic import (W1-00 review anticipated this); it resolves to `fixtures/dist` under the default export condition, which `npm run typecheck` (`tsc -b` over all references) emits and `npm run build` does not. The Playwright `webServer` command (W1-12) should run `npm run typecheck` or `npm run build -w fixtures` before `node server/dist/main.js`, or run `tsx --conditions=rai-source server/src/main.ts`. Without the table the process refuses with `fixture_outside_test`.
- **`case.create` scope step and lane/finding targets** are W1-02's and W2-02's: the middleware exposes `authorizeRequest()` (facts → authorize → 404) for the post-validation second call and the target kinds `none` / `case` / `artifact`; `lane` and `finding` targets are added by the W2-02 contract PR.
- **`request.completed` log line** remains W3-07's; this ticket emits `auth.signin.succeeded`, `auth.signin.failed`, `authz.denied`, `process.started`, `process.stopping` and `process.refused` only.
- **The W1-00 integration test** `w1-00-migrations.test.ts` was extended (table list and grants) because the schema now has one more table; no assertion was weakened.
- The `local-google` default-to-`owner` rule for unmapped accounts (W0-03 4.1, open item) is implemented as written and remains for the lead to confirm at this review.
- Board stream (`docs/board`) and DEVLOG entries are appended by the merge step, not by this PR.
