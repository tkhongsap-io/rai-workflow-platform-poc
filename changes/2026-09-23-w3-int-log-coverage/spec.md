# Test-harness contract proposal

The test-only observed buildApp preserves the real App/AppDeps interface and application behavior. It supplies a cloned test logger configuration with info-level JSON output and an audited Writable. It tees the exact serialized bytes to any caller-supplied stream without replacing its assertions, clearing its data or taking ownership of its lifecycle. Forwarding must respect write callbacks/errors/backpressure. The independent audit history cannot be cleared through the caller's capture reset.

Audit all serialized output, not selected event types. Reuse FIXTURE_FORBIDDEN and StringDecoder handling; do not print offending text in a failure. A sticky failure must survive callers catching an error, resetting their custom capture or rebuilding an app. Check after tests and after all tracked app/background work settles; do not close an app between tests when the suite intentionally reuses it. Final teardown uses the existing drain and bounded failure semantics, not an arbitrary grace sleep. Keep the auditor active for writes after close/final audit; an irreversible test-process failure signal must make such a leak fail even if its write exception is swallowed. Child-process controls must prove that behavior, not merely assert that a utility throws.

Mechanical guard: inspect integration entry points and reachable test helpers, resolving package/relative paths and aliases. Only observed-app.ts may value-import the real app factory. Reject named aliases, namespace imports, dynamic literal imports, require and helper re-exports that bypass it; type-only imports are permitted. Reject unresolved dynamic access capable of bypassing the factory rather than silently certifying it. Scan additions automatically instead of treating the current 17-file list as permanent proof.

Process paths retain startTestServer.stop's existing capture/assertNoLeak behavior. Confucius's three process tests and observability-database helper are outside this patch. Its current capture is child-exit based; this sidecar does not claim stream-close coverage or audit arbitrary external processes. OBS-15 closure must cite executed integration coverage plus import-policy and failing-leak controls, with those boundaries stated.
