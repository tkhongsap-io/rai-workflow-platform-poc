# Specification

Source: W4b plan section 15 row W4-06a and sections 3.1, 3.2 and 3.3 (decisions 10, 11, 22, 27, 28, 30). The plan wins over issue #221.

Done when:

1. **Runner.** `server/src/qc/content/runner.ts` `createContentQcRunner({ extractor, now?, runnerVersion?, onExtractFailed? })` implements `QcRunner` with identity `{ runner: 'content', runnerVersion }`. It executes only `engine: 'content'` rules through `CONTENT_RULES` and skips `metadata` rules. `rules === null` → `unavailable:not_configured` (`no_qc_rules_revision`); an unknown content rule, a trigger the rule is not defined for, params that fail the rule's schema, an unknown lane mapping or an approve attempt without a lane → `runner_error`; a `grammar+model` rule → `not_configured` (`model_disabled`), since no model port exists yet. All of these are decided before any byte is read. A request with no selected content rule completes with zero findings and reads no bytes.
2. **Lane scope** (decisions 22, 28). A rule's readable slots are: upload, `params.slots ∩ single-lane slots of the version's mapping ∩ the uploaded slot`; submit, `params.slots`; approve attempt, `params.slots ∩ slotsForLane(lane)`. Slot 9 is never read. A rule with no readable slot reads nothing, emits nothing and is still in `rulesEvaluated`. Content findings are owned by the slot's single lane on upload and by the run's lane on an approve attempt.
3. **Bytes.** Each artifact in a readable slot is read once per run, up to `byteLength` bytes; a `read()` rejection is `artifact_unreadable` / `blob_missing`, more bytes than `byteLength` or a sha256 other than `contentHash` is `artifact_unreadable` / `hash_mismatch`, a media type outside the upload allow-list is `artifact_unreadable` / `extract_unreadable`. Each artifact is extracted once. `unreadable` or `limit_*` → `artifact_unreadable` / `extract_<reason>`; `crash` or a thrown extractor → `runner_error` / `extract_crash`; an aborted signal → `timeout`. A failure calls the optional `onExtractFailed({ slot, reason, durationMs, extractorVersion })` hook (no text). A run that extracted reports `engine.extractorVersion`.
4. **Claim grammar** (`qc/content/claims.ts`, WA-D09). XLSX: per sheet, the first row whose cells match at least three column keys is the header; every later row with an answer cell is a claim, located at the answer cell, excerpt = the row's non-empty cells in column order joined by U+001F. DOCX/PDF: a segment of `key: value` pairs separated by `;` with at least one `answer` key is a claim, located at the segment's locator, excerpt = the segment text. Keys and answers match the rule's bilingual `params.labels` after NFC, case folding and whitespace collapse; answers normalise to `yes | no | na | unknown`; items come from `params.items` keywords found in the `question` or `item` field. Values: `%` → `percent`, a bare number at most 1 with a decimal point → `ratio`, otherwise `count`.
5. **Decimal and excerpt.** `qc/content/decimal.ts` parses decimal strings and compares them exactly as scaled bigints (`compareDecimal`). `qc/content/excerpt.ts` `excerptHashOf` is sha256 hex of the NFC UTF-8 text; `claimKeyOf` is its first 16 hex characters.
6. **ACC-METRIC-CITED.** Fires on a `yes` claim on the `hallucination` or `accuracy` item that lacks an accepted metric (`params.acceptedMetrics`; an extraction metric counts as absent), a parseable value, denominator or threshold, or evidence. One finding per defective claim: artifact scope, evidence = locator plus `excerptHash`, `claimKey`, severity from the catalogue, message `qc.finding.acc_metric_cited` with params `{ slot, missing, item? }` (`missing` a comma list of field keys in the order metric, value, denominator, threshold, evidence; `item` only when it is an item reference). `measure` carries the stated metric and value (denominator and threshold null when missing, unit from the value, `thresholdSource` the version's template) when both are stated, and is `null` otherwise. Never fires on complete evidence. Two claims with the same text in one artifact are one finding with one evidence entry per occurrence.
7. **Findings contract** (`shared/src/qc/{types,validate}.ts`). `QcFinding.claimKey?` (`^[a-z0-9_]{1,64}$`); `findingKeyOf(ruleId, scope, claimKey?)` appends `:${claimKey}` when present, so every existing key is unchanged. `QcFindingContext.artifacts?` is optional; when present, `evidence_outside_request` refuses evidence citing an artifact not in the request (or with another hash or slot). `message_param_text` refuses a string param that is not a key, a comma list of keys, an item reference, a decimal string or exactly the request's template version. `duplicateFindingKey(findings)` returns `duplicate_finding_key` for two findings with one key; `checkedResult` applies it to every runner's completed result (`runner_error`).
8. **Catalogue.** `QC_RULE_PARAMS_SCHEMAS['ACC-METRIC-CITED']` (slots 1-8, bilingual labels, items, accepted metrics, `claimSource`), and the seed's `ACC-METRIC-CITED` entries in both templates carry params (`claimSource: 'grammar'`); the seed label stays `w4a.1`; `seed.test.ts` "every seed body validates" stays green.
9. **Substitute.** Every bundled script's findings pass `validateQcFinding` against their fixture request, and, on approve attempts, against the context literal the frozen API substitute's `storeableFindings` builds, so it drops none. No script needed correcting.
10. **Module graph.** `qc/content/` imports no network module, `pg`, `drizzle-orm`, `server/src/db/`, `server/src/artifacts/` or `child_process`, and holds no dynamic import.
11. **Documents.** Dated notes on W0-07 3.4 step 5 (lane-scoped content reading, decision 28) and 3.5 (the `ACC-METRIC-CITED` content rule row).
