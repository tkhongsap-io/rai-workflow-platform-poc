## Deviations, defaults and limitations (for the reviewer)

- **Three contract fields infer as `never`** in `@rai/shared` today: `ModelTypeSchema` (`schemas/cases.ts`), `StageContextSchema` (`schemas/slots.ts`) and `AllowedMediaTypeSchema` (`schemas/artifacts.ts`) are built with `LIST.map((v) => Type.Literal(v))`, which TypeBox 1.3 infers as `never`, so `CaseWritableFields['modelType']`, `PackDraft['stageContext']` and `ArtifactRef['mediaType']` are `never` at compile time (the JSON is unaffected; `schemas/auth.ts` already notes the trap and spells its tuple out). This ticket does not edit the shared contract; `contract-cast.ts` narrows at the three construction sites and says so. **Request to Lane A**: a one-line contract PR spelling the three tuples out (the way `auth.ts` does) before W1-02/W1-03/W1-06 hit the same wall; the casts then become identity functions and can be deleted.
- **The upload sniff is an approximation.** W0-08 checks 1-8 and 10 are reproduced with the section 5 keys; the structural checks (2.1 PDF active-content scan, 2.2 ZIP rules, PNG/JPEG rules; check 9) belong to W1-03's product sniffer and are not duplicated, so a file the substitute accepts may still be refused by the server. The README says so.
- **In-browser bundling is not the delivery path.** `@rai/fixtures` computes fixture ids with `node:crypto` (`data/ids.ts`, W1-09), so the substitute cannot be bundled into the SPA by Vite as-is; `VITE_API_SUBSTITUTE=true npm run dev -w web` is served by running `serve.ts` on the port the Vite proxy targets (127.0.0.1:8787), which is what the plan's section 3.4 line asks for functionally. If Lane B wants the substitute inside the bundle, `fetch.ts` is the adapter, and making `fixtureUuid` browser-safe is a W1-09 follow-up, not this ticket.
- **`isLatest` on a frozen version** is flipped to `false` when a later version is pushed; in W1 no second version can exist (submit needs a draft and none reopens until W2-03), so every W1 read is byte-identical as 7.6 promises. W2-10 revisits this with the successor-draft rule.
- **`caseRevision` is not incremented by submit**: the submitted version freezes the revision the client saw (W0-06 5.1); a later PATCH is refused with `version_superseded` because no draft is open, whatever revision it names.
- **Registry ids** for cases created through the substitute are `RAI-<current year>-<nnnn>` from a per-process counter; fixture cases keep the reserved year 2000, so the two never collide.
- **`docs/architecture/README.md`** unchanged: its boundary table's "Path in repo" column already names `rai-web/fixtures/src/substitutes/api/` through W0-02 section 1.1.
- **Observed on `main`, outside this ticket**: PRs #68 (W1-11) and #69 (W1-10) are recorded as merged, but their merge commits (`4eea867`, `e8ba91a`) are not ancestors of `origin/main`, so `fixtures/src/substitutes/{qc,mail-sink}/` are absent from `main`. W1-13 depends only on W1-00 and W1-09 and is unaffected; reported for the lead.
