## Change

- **`server/src/config.ts`**: `parseQcMode(env, nodeEnv, identityMode)`. `deterministic` parses in every `NODE_ENV` and identity mode. `substitute` parses only outside `NODE_ENV=production` and with a local identity mode (`fixture`, `local-google`; `IDENTITY_MODES` also has `network` and `production`); otherwise `invalid:QC_MODE`. Unset or blank stays `missing:QC_MODE`, any other value `invalid:QC_MODE`. The constant is `QC_LOCAL_IDENTITY_MODES`: `w1-int-substitute-absent.test.ts` forbids the word `SUBSTITUTE` in `config.ts` outside `'substitute'`, and caught the first name.
- **`server/src/start.ts`**: the runner is `overrides.qcRunner ?? (deterministic ? createDeterministicQcRunner : the scripted substitute from @rai/fixtures)`. The production non-binding branch is gone (config refuses that case). Neither mode falls back to the other: `substitute` without the fixtures package stays unbound (`disabled`), and `deterministic` never imports the substitute. Readiness `qc.kind` is `qcKindOf(runner.identity)` for a bound runner and the configured `QC_MODE` otherwise; the hard-coded `'substitute'` is gone. The test-override guard (`NODE_ENV=test`, fixture identity, loopback host) is unchanged; `start-overrides.test.ts` passes unchanged.
- **`tests/support/fixture-app.ts`** (integration harness): readiness `qcKind` comes from the injected runner's identity (`qcKindOf`) instead of the constant; with no runner it stays `substitute`.
- **`.env.example`**: `QC_MODE=deterministic`, with a comment on the substitute's refusal and the test pins.
- **Pins (no change needed)**: CI already sets `QC_MODE: substitute` in its top-level `env` (`.github/workflows/ci.yml`); every spawned test server gets `QC_MODE: 'substitute'` from `tests/support/process.ts` `testServerEnv`, the evidence browser child also from `tests/browser/support/real-server-lifecycle.ts`, the journey server through `testServerEnv`, and the performance harness from `tests/performance/server-env.ts`. The substitute Playwright configuration starts only the in-memory API substitute and Vite, which read no `QC_MODE`. `tests/browser/playwright.config.ts` gains a header note naming the pin.
- **Comments** updated: `qc/deterministic/runner.ts`, `w4a-int-deterministic-server.test.ts`, `fixtures/src/substitutes/qc/config.test.ts` (its "not in config.ts today" note).
- **Docs** (dated W4-13 amendments): W0-02 section 5 (`implementation-plan-w1-w3.md`, after the key table); W0-07 end of 3.9 and section 6 (`qc-boundary-and-mail-sink.md`): the real value arrives in W4a without ADR-0006, which stays W4b's, and the production refusal; `TESTING.md` W4a paragraph (the pin and the real-server test command from plan section 8).

  - `server/src/start.test.ts` (+4): `deterministic` under local-google/development binds and readiness reads `{ kind: 'deterministic', status: 'ok' }`, with the fixtures package absent and the substitute module never imported; `substitute` with the fixtures package absent reads `{ kind: 'substitute', status: 'disabled' }`; `substitute` under network/development and under local-google/production exits 78 with exactly one `process.refused` line `invalid:QC_MODE` and nothing listening.

## Deviations

- **Existing test expectations changed by plan.** (1) The W4-03 `config.test.ts` test asserting `deterministic` is refused outside `NODE_ENV=test` is replaced, because plan section 2 makes it valid everywhere. (2) `static.test.ts` "in production an absent web build refuses to start ... missing:web/dist" used `QC_MODE=substitute` with `production` identity; that configuration is now refused first with `invalid:QC_MODE`. Its production env now uses `deterministic`; the assertion (`missing:web/dist`, exit 78, nothing listens) is unchanged.
- **Item 5 (real-server test asserts `qc.kind === 'deterministic'`)** was already on main from W4-03 round 2; nothing to add beyond the header comment.
- **Evidence Playwright configuration.** Plan section 2 says it sets `QC_MODE` "for its web server". `tests/browser/playwright.config.ts` has no `webServer`: the evidence child is started by `support/real-server-lifecycle.ts` through `tests/support/process.ts`, both of which already set `QC_MODE: 'substitute'` over whatever `.env` says. No behaviour change was needed; the config header now says where the pin lives. Proof: both browser suites below ran with `rai-web/.env` at `QC_MODE=deterministic` (copied from the new `.env.example`) and passed unchanged.
- **CI unchanged.** `.github/workflows/ci.yml` already pins `QC_MODE: substitute` at workflow level (since W1-12), so the PR does not touch `.github/`.
- **Readiness kind when no runner is bound.** The plan says the kind comes from the bound runner; when `substitute` cannot load (no fixtures package) no runner is bound. It reports the configured mode (`substitute`, status `disabled`), the smallest option consistent with "never a constant" and with the previous report for that case.
- **Integration harness readiness.** `tests/support/fixture-app.ts` also hard-coded `qcKind: 'substitute'`; it now follows the injected runner like `start.ts`. No suite asserted the old value with a deterministic runner.
- **`compose-app-deps.ts` and `observability/health.ts`** (plan section 9 paths) needed no change: `health.ts` takes `qcKind` from its caller, and `qc.run.started` already reads `qcKindOf` since W4-11a.
