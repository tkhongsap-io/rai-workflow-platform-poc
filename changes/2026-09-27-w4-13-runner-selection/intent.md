# Intent: runner selection, QC_MODE binds the real runner (W4-13, #187)

W4-03 added the `deterministic` QC runner and let `QC_MODE=deterministic` bind it only under `NODE_ENV=test`, for the real-server test. Every other environment still runs the scripted substitute, and in production the substitute is silently left unbound (`start.ts`), which makes a production process run with no QC and no refusal. W0-07 3.9 has always said the loader refuses `production` identity with `QC_MODE=substitute`; `config.ts` never did.

This ticket makes `deterministic` the runner of every environment and makes the substitute a local-only value: start refuses `QC_MODE=substitute` with `invalid:QC_MODE`, exit 78, under `NODE_ENV=production` or a non-local identity mode (`network`, `production`). Unset and unknown values keep refusing. No runner falls back to the other. Readiness `qc.kind` comes from the bound runner (or, when the substitute cannot be loaded, from the configured mode), never a constant. `.env.example` sets `deterministic`; CI and the evidence harness keep `substitute` explicitly, so no existing suite changes behaviour. It is the fourth W4a ticket (plan section 9, order 4) and implements [W4a plan](../../docs/engineering/implementation-plan-w4a.md) section 2 under the register rows "W4a gate entry", "D05 refinement (upload slot 5 and 9)" and "W4a kickoff rulings" (Ta, 2026-09-26).

Not here: the upload trigger (W4-04), the QC log UI and qc-runs endpoint (W4-12), ADR-0006 and any content or model runner (W4b). Synthetic data only; no document parsing, model, provider or network call.
