# H26: The submitted-version read carries its lane decisions, including send-back feedback

Found by the walkthrough re-verification on main `9103668`. The finding still applied on that commit.

## Finding addressed

- **Send-back feedback had no read shape (medium; A09, W0-06 section 5 send-back postconditions).**
  - Send-back stored `lane_decision.feedback` and used it only to compose the owner's mail. No response returned it, so an owner told to "revise per the feedback and resubmit" could not see the feedback in the app. `SubmittedVersion` still carried the comment `// W2 contract PRs add: lanes, decisions, findings, dispositions`.
  - Reproduced first. The new W2-02 test and the extended W2-03 test both failed on main (`decisions` was `undefined`, expected `[]`).
  - Contract: `SubmittedVersion.decisions: LaneDecision[]` replaces the comment. `LaneDecision` (`shared/src/schemas/review.ts`) is `{ lane, decision: 'approve' | 'send_back', decidedBy, decidedAt, feedback: SendBackFeedback | null }`. It reuses `SendBackFeedbackSchema`, and `decidedBy` is the subject id, the same convention as `submittedBy`. The response's `decision` literal union is now defined once and shared with `LaneDecisionResponseSchema`. W0-02 section 7.6 of `implementation-plan-w1-w3.md` carries the same text, and 7.7 points at it.
  - Server: `listLaneDecisions` (`workflow/repository.ts`) reads every `lane_decision` row of the version, ascending by `decided_at` then lane. `GET …/versions/{versionId}` and `GET …/versions/latest` serve it with no new route. They run under the same `version.view` authorization, so anyone who can read the version can read its decisions. The case row, the version row, the slots and the decisions are read in one `repeatable read`, read-only transaction, so `isLatest` and `decisions` describe the same instant. The submit `201` and its replay carry `decisions: []`, because nothing is decided at the freeze.
  - No migration. Feedback is not logged, and the `lane.sent_back` audit still carries only `feedback_item_count`.
  - The version read is no longer byte-identical for the life of the row. The frozen fields still are. `isLatest` already changed after a resubmit, and `decisions` now grows as lanes decide. The 7.6 table row and the route's schema comment say this now.

## Tests (fail before, pass after)

- `w2-02-lane-decision.test.ts`: new test, "the version read carries its decisions: none before, approve without feedback, send-back with it; scope unchanged". It checks four things. Before any decision the read returns `decisions: []`. After a DPO approve and an AI/COE send-back, the by-id and `latest` reads return both decisions, the approve with `feedback: null` and the send-back with its items and summary. The feedback text appears in no captured log line. An out-of-scope owner still gets 403 on both reads.
- `w2-03-successor-draft.test.ts`: after two concurrent send-backs, version N's read returns both decisions with their own feedback, ordered by lane at the shared instant.

## What got smaller

`readVersion`, `latestVersion` and `viewOf` in `versions/service.ts` were two near-copies plus a helper. They are now one snapshot reader, `readView`, and two one-line exports. The `approve | send_back` union in `review.ts` is defined once instead of twice. The added lines are the contract field, one repository read, the tests and the contract text.

## Outside the batch's own files

- `web/src/screens/case/view-model.test.ts` (listed under H25): its `baseVersion()` builder gains `decisions: []`, because `SubmittedVersion` now requires the field and `npm run typecheck` fails without it. This is the one line that touches H25's files; the branch was rebased onto H25 (db729fd) before review.
- `fixtures/src/substitutes/api/routes-versions.ts`: the typecheck also needs the field here. The substitute stores `decisions: []` and always serves it. That drift is listed in its README. The UI is unchanged (H27 consumes the field).
