# H19: Composition root reads as composition: fixture-import failures surface, one clock spread, build identity derived once

## Findings addressed

All five findings still applied on main `cf87c13`.

- **Fixture and QC dynamic imports swallow every error (architecture resilience, low; the bug, fixed first and tested first).** On main, both `loadFixtureUsersModule` and `loadQcSubstituteRunner` ended in `catch { return undefined; }`. A fixtures package that is installed but broken (a syntax error, or `fixtures/dist` missing a file) started the server with no BU keys and no QC runner, and logged nothing. Now one `importFixtureModule` helper treats only `ERR_MODULE_NOT_FOUND` naming `'@rai/fixtures'` as "absent" and rethrows anything else. `startServer` loads every fixture input before it opens the database or starts the identity adapter, and maps any failure to `refuse('fixtures_import_failed')` (exit 78). An absent package, as in a production install, still degrades as before.
  - **Deviation from the batch text:** the batch spec also matched `ERR_PACKAGE_PATH_NOT_EXPORTED`. Node 24 never names the package in quotes in that error. It prints `Package subpath './nope' is not defined by "exports" in /…/node_modules/<pkg>/package.json`, checked with `import('typebox/nope')`. That branch could never match, so it is left out. A missing package gives `Cannot find package '@rai/fixtures' imported from …` and is matched. A file missing inside an installed package gives `Cannot find module '/…/@rai/fixtures/dist/…'`. That is a broken build, so it refuses.
- **start.ts mixes the loaders, repeated option spreads and ticket history (runtime-ops simplify, low).** `ConfiguredQcRunner` is declared once, above `StartOverrides`, and the override uses it. One `clock` spread replaces the nine `...(overrides.now === undefined ? {} : { now: overrides.now })` spreads. The loaders now read typed module shapes (`FixtureUsersModule`, `FIXTURE_CASES`, `ScriptedQcRunner`) instead of re-validating the repository's own package field by field. The two `data/users` loaders become one import whose two exports are read at the call site. The `bind` object is inlined, the duplicate `config.js` import is merged and the duplicated owner-recipient closure is written once. The `W1-02:`, `W1-04:`, `W1-05 / W2-01:`, `W2-02:`, `W2-05 / W2-06 / W2-INT:` and `W1-INT:` block comments are now one-line reasons, or deleted. The loaders stay in `start.ts`, and the registration style is unchanged.
- **Build/schema identity hard-coded (runtime-ops simplify, low).** `schemaVersion` is derived once in `start.ts` as `String(migrationFileCount())`, using the existing `db/migrate.ts` helper. The same value goes to readiness (`build.schemaVersion`) and to `startedFields(config, schemaVersion)`. Before, readiness hard-coded `'unknown'` and `process.started` hard-coded `'unknown-until-W3-07'`, so the two surfaces disagreed. `health.ts` defines one `unsetIdentity` constant and uses it in both fallback branches. `BUILD_COMMIT` handling is unchanged, as specified. `started.ts` keeps its module (the spec asks for a parameter). Its header now names `start.ts` as the caller, not `main.ts`.
- **Comments narrate ticket history (app.ts and start.ts part).** The `app.ts` header is now five lines stating purpose and invariants: the correlation id, the error envelope, authz as the only place scope is enforced, and routes registered per deps. The `W1-0x:` and `W2-0x:` prefixes on `AppDeps` are removed. The `start.ts` header and overrides lose their ticket IDs and keep the spec citations (W0-03 S16, W0-04, W0-08). `shutdown.ts` loses "found by the W1-INT review".
- **shutdown.ts duplicates the idle-wake check (runtime-ops simplify, low).** `createDrain` has `idle()` and `wakeIfIdle()`, which are used by the response-close hook, `untilIdle` and `track`. `inFlight()` stays on `Drain`, and its doc comment names it as the test seam.

`notifications/runtime.ts` is unchanged. `loadMailSink` already fails loudly on any import error, and the spec keeps the loader locations.

### Tests that fail before and pass after

In `server/src/start.test.ts`, against the new `importFixture` override:

- `a fixtures import failing with a syntax error refuses to start with fixtures_import_failed`, and the same test for `an unbuilt module inside the package` (ERR_MODULE_NOT_FOUND on a file inside `@rai/fixtures`). On main both servers started, and `assert.rejects` failed.
- `an absent fixtures package (a production install) starts with no fixture BU keys and no QC runner`. It pins the branch that must still degrade: the BU list is `[]` and readiness reports `qc.status` as `disabled`.
- `ID-02 control` now also asserts `build.schemaVersion === String(migrationFileCount())`. On main it failed with `actual: 'unknown', expected: '9'`.

`observability/started.test.ts` passes the schema version and expects it back.

## What got smaller

- `server/src` production code: 124 lines added, 163 removed (net -39). `start.ts` went from 308 to 271 lines (-37), even with the new refusal path, the `importFixture` seam and the missing-package check added. The "about 100 lines" in the batch estimate assumed the loaders would leave `start.ts`. The batch's own fix keeps them there, and each `now` spread was already one line, so replacing it saves no lines.
- Removed: two catch-all `catch { return undefined; }` blocks, the second `data/users` import function, field-by-field re-validation of the repository's own fixture exports, nine conditional `now` spreads, one repeated recipients closure, two hard-coded schema versions, one duplicated identity fallback literal and three copies of the idle check.
- Tests: 63 lines added, 3 changed.

## Docs

`TESTING.md` covers two points. The built server imports `@rai/fixtures/data/users` in every mode (for the BU keys). An installed package that fails to import refuses with `fixtures_import_failed`, and the fix is `npm run build -w fixtures`. The local-google runbook's refusal list adds the new code.
