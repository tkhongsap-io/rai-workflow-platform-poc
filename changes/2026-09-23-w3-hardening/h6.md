# H6: CSRF guard on every state-changing route

## Finding addressed

- **security-crosscut (medium): only sign-out checked same-origin, so every other state-changing route accepted cross-site and same-site requests.** `SameSite=Lax` keeps the session cookie off cross-site requests but still sends it on same-site ones. That covers another app on loopback at a different port, because cookies are not port-isolated, and sibling subdomains on a True host. A page there could auto-submit a multipart form to `POST /api/cases/<id>/artifacts` (a simple request, so no preflight), and the file would be planted on the victim's draft under the victim's identity. It reproduced on main before the fix: the new test's `cross-site` and `same-site` rows got `201` on the upload.

## Change

- `rai-web/server/src/authz/middleware.ts`: the `onRequest` hook refuses a request right after its 401 check when all of these hold: the route is not `public`, the method is not `GET`, `HEAD` or `OPTIONS`, and `Sec-Fetch-Site` is present with a value other than `same-origin` or `none`. The response is 403 `forbidden`, and one `authz.denied` line is logged with reason `cross_site` on the existing W0-10 field list. The check runs before any body parsing, so a multipart stream is never read. An absent header is allowed, because browsers always send it and a non-browser client carries no ambient cookie. `emitDenied` now reuses the policy's `DenyReason` type instead of repeating its four literals, and it accepts a session route that has no policy action. The stricter sign-out check in `identity/routes.ts` is unchanged, and it still refuses an absent header.
- Docs: W0-03 (`docs/engineering/identity-adapter.md`) gains a section 6.1 paragraph and a section 6.4 row. W0-10 (`docs/engineering/observability-contract.md`) registers `cross_site` on `authz.denied`. `TESTING.md` gets one sentence on the sign-in surface.
- The W0-05 policy matrix needs no change: `cross_site` is not a policy `Decision.reason`, because `authorize` never runs for it.

## What got smaller or clearer

- The deny-reason union was listed twice, once in `policy.ts` and once in `middleware.ts`. It is now listed only in `policy.ts`.
- No new abstraction or dependency. The whole guard is one condition inside the existing hook.

## Tests

- New file `rai-web/tests/integration/w3-hardening-cross-site-guard.test.ts` (5 tests):
  - With `cross-site` and with `same-site`, an owner's multipart upload and a locale POST each get 403 with the plain envelope. No artifact row, blob, temp file or audit row is written, and the locale is unchanged. There is exactly one `authz.denied` `cross_site` line per request, matched by correlation ID. A GET with the same header still gets 200.
  - With `same-origin` and with no header, the same upload gets 201 and the locale POST gets 204.
  - Without a session, a cross-site write gets 401 and emits no `authz.denied`.
- Before the fix: 3 passed, 2 failed (the `cross-site` and `same-site` rows got `201` instead of `403`). After the fix: 5 passed.
