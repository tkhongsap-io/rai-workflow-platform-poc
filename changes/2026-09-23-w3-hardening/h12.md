# H12: offer 'New case' only to roles that can create; render the specific unsafe_upload reason

## Findings addressed

- **web-ui bug (low): 'New case' was offered to reviewers and Admin, who can only get 403.** Still reproduced on main `1b4d49e`: the shell nav, the queue header and the case-list header and empty state all linked to `/cases/new` for every signed-in user, while `case.create` holds rows only for `owner` and `bu_spoc` (`server/src/authz/policy.ts` `WRITE_ROLES`). The new w1-int-07 assertions failed before the fix (the link was present for `fx-user-ai-coe`, `fx-user-dpo`, `fx-user-it-security` and `fx-user-admin`, and twice on the DPO's queue).
- **web-ui (medium): `unsafe_upload` `details.reasonKey` was never rendered.** Still reproduced: an empty file in the slot dialog showed only the generic `error.unsafe_upload` line, so the 13 `error.unsafe_upload.<reason>` messages were dead copy. The new w1-int-06 case failed before the fix on the missing `empty_file` text.
- **web-ui simplify (low), error-notice.tsx part only: the file header narrated ticket IDs.** The other files that finding lists (`reviewer-workspace.tsx`, `disposition-controls.tsx`, `case-screen.tsx`, `operator-labels.ts`, `dialog.tsx`) belong to H5 (#139), which already rewrites them.

## Change

- `web/src/screens/operator/desk-health.view-model.ts`: `canCreateCase(session)` beside `isOperatorAdmin`, presentation only: true when some role is `owner` or `bu_spoc`. It gates the shell nav link (`app-shell.tsx`), the queue header link (`queue-screen.tsx`) and the case-list header and empty-state links (`case-list-screen.tsx`, now one shared element). The server still decides; the reviewer 403 test stays.
- `web/src/api/client.ts`: `ApiError.unsafeUpload` returns the `unsafe_upload` details, like `stale`. `describeError` copies `reasonKey` and `reasonParams` from it, and `ErrorNotice` renders `translateApiKey(t, reasonKey, reasonParams)` under the generic line, so limit placeholders such as `{max_file_mb}` are filled.
- `web/src/components/error-notice.tsx`: the 5-line header is 2 lines stating the invariant (locale keys from the envelope only, no response text, no permission rule); the `children` doc drops its ticket reference.
- Tests: `desk-health.view-model.test.ts` (owner, SPOC, DPO+SPOC dual role true; Admin and DPO false); `client.test.ts` (`unsafeUpload` exposed for `unsafe_upload` only); `w1-int-07` (each of the eight fixture users: the nav link present for the owners and SPOCs including the DPO+HR-SPOC, absent everywhere on the page for AI CoE, DPO, IT Security and Admin; the DPO's queue has no link; the reviewer 403 test opens `/cases/new` with `page.goto`); `w1-int-06` (the slot dialog refuses an empty file with the `empty_file` text and an axe pass, then a 25 MiB + 1 byte file with the `too_large` text naming 25 MB, and the slot stays `missing`).
