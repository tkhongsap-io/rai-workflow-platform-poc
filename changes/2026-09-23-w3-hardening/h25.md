# H25: Reviewer workspace: no false "Action failed" after a successful send-back

The walkthrough re-verification on main `9103668` found this, and this batch reproduced it on that commit before changing anything.

## Finding addressed

- **False "Action failed" after send-back (medium).** A lane reviewer's send-back succeeded and the green `review.decided.send_back` notice appeared. The same page then showed the red error notice ("your action was not recorded"). `reviewerFindingsLoadMode` returned `lane_qc` for any lane on a case that was not Ready. After `onDecided` refreshed the view, the workspace therefore POSTed `…/lanes/{lane}/qc-run` on a version that now had an open successor draft. The server answers that with 409 `version_closed`, which is correct and unchanged.
  - `reviewerFindingsLoadMode({ lane, view, hasOpenDraft })` now returns `lane_qc` only when `laneIsDecidable` holds: not Ready, no open successor draft, lane projection `pending`. Every other case, including the owner/BU-SPOC panel, reads the stored findings through `GET …/versions/:versionId/findings`. The rule lives in `laneIsDecidable` alone.
  - An approved lane also stops re-running lane QC. On main that call replayed the lane's completed run, so it showed no error, but it was a mutation-route call with nothing left to approve.
  - The workspace no longer checks `laneIsDecidable` a second time before drawing approve and send-back. A run is loaded only while the lane is decidable, and a change in decidability changes the load key, so `state.run !== null` already carries that check.

## What got smaller

`reviewer-workspace.tsx` imports one view-model function fewer and draws the decision controls on one condition instead of two. The load mode no longer restates part of the decidability predicate. It calls it.

## Tests

- `web/src/screens/case/view-model.test.ts`: the old test asserted that a non-Ready approved lane still runs lane QC. It is replaced by one that covers every case. A pending lane gets `lane_qc`. A Ready case, an open successor draft, the lane's own approved or sent-back projection, and the proposal panel get `persisted`. Another lane's decision leaves a pending lane on `lane_qc`. On main `9103668` it failed (`ai_coe Ready`: actual `lane_qc`, expected `persisted`, since the old function took `(view, lane)`). After the fix all 15 tests in the file pass.
- `tests/browser/w2-int-journey.spec.ts` (the W2-INT send-back journey): `decideThenReadStoredFindings` wraps the AI/COE send-back and each of the three approvals. It waits for the workspace's first load after the decision and requires it to be `GET …/findings`, not a qc-run. It then requires no `[data-review-qc="loading"]` and no `role="alert"`. With the main `web/src/screens/case` files restored, the spec failed at all three widths on the send-back: `Received string: "POST /api/cases/…/versions/…/lanes/ai_coe/qc-run"`. After the fix it passes at all three widths.
