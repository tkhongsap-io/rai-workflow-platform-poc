# H24: Final-verification follow-ups

The final verification after H1-H23 merged found these. All of them still applied on main `4522074`.

## Findings addressed

- **Integration hangs after `cp .env.example .env` (medium).**
  - Reproduced on main with `DATABASE_OPERATOR_URL` empty: `w3-int-browser-lifecycle.test.ts` failed its busy-child test and the file never exited. A 180 s alarm killed it, with no summary line. The observer client had no connection string, so pg fell back to port 5432. The blocker client was already connected, and nothing closed it.
  - `.env.example` now ships `DATABASE_OPERATOR_URL=postgres://rai_operator:rai_operator@127.0.0.1:54320/rai`. That is the synthetic role `docker/postgres/init/001-roles.sql` creates, and its port follows `POSTGRES_PORT` like the two lines above it. The W0-02 variable row in `implementation-plan-w1-w3.md` and the handoff row in `persistence-and-artifact-store.md` now say the same.
  - The lifecycle test builds its observer from `operatorUrlForTests(env)`. It connects both clients inside the `try`, and its `finally` ends the blocker first. Ending the connection rolls back the row lock the explicit `ROLLBACK` used to release, and pg's `end()` returns at once for a client that never connected. A failed connect therefore cannot leave a socket open.
  - `late-submit-scenario.ts` and `submit-binding-scenario.ts` read `env.DATABASE_OPERATOR_URL` from the env that `withIsolatedFixtureDatabase` hands them, and that env always sets it. With an empty variable it was the `rai_owner` URL, because `parseDatabaseConfig` falls back to `DATABASE_MIGRATE_URL`. So the fix goes where the URL is resolved. `tests/browser/support/isolated-database.ts` now takes the operator URL from `operatorUrlForTests(env)`. That covers both scenarios, and the four browser specs that read the same field, with one line.
  - With the variable empty, the lifecycle file now passes (10/10 in 4 s). With it pointing at a closed port, the file fails in 2 s with `connect ECONNREFUSED`. The full suite with it empty fails fast: 2 fails in 167 s, both `w3-int-observability` tests, each saying `explicit DATABASE_OPERATOR_URL required`. That preflight is intentional, and `w3-int-observability` asserts it. The final verification reported that run on main as 3 fails and 1 skip, then a hang of about 11 minutes. This batch reproduced the hang on the lifecycle file alone (table below).
- **TESTING.md commands lagged package.json (low).** Checked against `package.json`, both Playwright configurations and `tests/performance`:
  - `test:unit` covers `tests/performance/*.test.ts`.
  - `typecheck` is `tsc -b . tests/performance`.
  - The real-server browser config runs every `*.spec.ts` except `*.substitute.spec.ts`.
  - `perf:run -- <plan.json>` is listed, with the port-54370 guard in `tests/performance/profiles.ts`.
  - One sentence covers `PLAYWRIGHT_BASE_URL`, `SUBSTITUTE_PORT` and `SUBSTITUTE_WEB_PORT` for parallel worktrees. The configurations read them from the process environment when they load, and the substitute configuration never reads `.env`, so the sentence says to set them in the shell.
  - The Postgres line names all three `DATABASE_*_URL` values.
  - The sign-in paragraph notes that sign-out is the exception to "a request without the header passes".
- **identity-adapter.md section 6.4 (low).** Every error envelope's `messageKey` is `error.<code>` (`messageKeyFor` in `shared/src/errors.ts`). The 401 rows are `error.unauthenticated` and the refused-login and sign-out rows are `error.forbidden`. The sign-out row covers only a missing header (the route's own check in `identity/routes.ts`). A cross-site value is refused first by the guard in `authz/middleware.ts`, so the next row now reads "any non-`public` write, sign-out included". The intro says the section 12 `auth.*` keys are sign-in-screen display keys, never a response `messageKey`. Row ID-11 and the `GET /auth/callback` row of implementation-plan-w1-w3.md now give the same keys (`error.unauthenticated`, `error.forbidden`), and the intro no longer claims the sign-in screen displays the `auth.*` keys today.
- **observability-contract.md 3.3 (low).** `request.completed` (`app.ts`) omits `actorSubjectId` and `actorRole` on public routes and on requests without a session. It also omits `actorRole` when the actor holds more than one role. `authz.denied` (`emitDenied`) carries every role, comma-joined.
- **Substitute README (low).** New section "Known drift from the server (rehearsal only, never evidence)". Approve checks only that `qcRunId` is a UUID: there is no `lane_qc_not_run` for a missing run and no `qc_run_superseded`. The substitute keeps its own UUID check and undispositioned predicate. Deleting it waits on Ta. The substitute code is unchanged.
- **later-packages-outline.md W7 (low).** The W7-00 networked-rehearsal clause records a deferred item. Before the first non-loopback bind, `network` mode must refuse a non-`https` `PUBLIC_BASE_URL`, and W0-03 row S17 is amended then. No code change: W7 is not authorized.
