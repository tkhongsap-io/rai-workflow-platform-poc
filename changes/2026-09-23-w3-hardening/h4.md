# H4: pool and process resilience

Hardening item 3 of the [spec](spec.md), the pool and process half. Synthetic data only; no product rule changes.

## Findings addressed

1. **An idle-client error from the pg Pool crashed the server, and pool connects had no timeout.** `createDb` now
   builds the pool with `connectionTimeoutMillis: 5_000` and a no-op `error` listener, so an operator command or a
   test pool survives Postgres terminating an idle client. `startServer` adds a listener that reports the error
   through the existing redacted capture (`errors.internal`, one `error.captured` line); the pool drops the dead
   client and the next request connects afresh. The optional `onIdleError` parameter the batch proposed was left
   out: the server's listener needs `errors` from `buildApp`, which exists only after the pool, so the option would
   have had no caller.
2. **No process-level fatal handling; fatal paths bypassed the redacted log.** `main.ts` has one `fatal(err)`: one
   `error.captured` line on stderr (module/line stack only, no message, `correlationId` null, `strict: false` so it
   cannot throw), then exit 1. It is installed for `uncaughtException` and `unhandledRejection` before
   `startServer`, replaces the duplicated `main().catch` body, and handles a rejected `close()` during shutdown,
   which previously exited 1 without a line.

## What got smaller or clearer

- `main.ts`: the inline `main().catch` logger and the silent `() => process.exit(1)` close branch became one named
  `fatal` used in four places.
- The fault injection for the spawn test is a test-only preload (`tests/support/fixtures/leak-rejection-preload.ts`,
  loaded through `NODE_OPTIONS=--import`); the deployable carries no fault flag, and the built `server/dist` contains
  neither the preload nor a `SIGUSR2` handler.

## Tests (each fails on main, passes here)

- `rai-web/server/src/db/client.test.ts`: a connect to a socket that accepts and never answers gives up after 5 s
  (on main it was still connecting after 10 s).
- `rai-web/tests/integration/w3-h4-pool-idle-error.test.ts`: `pg_terminate_backend` on the server's `rai-desk`
  backends while it idles; one `error.captured` line, the process stays up, the next signed-in `GET /api/cases`
  answers 200 and SIGTERM still exits 0 (on main the process exited 1).
- `rai-web/tests/integration/w3-h4-fatal-handler.test.ts`: a synthetic unhandled rejection whose message carries the
  database URL gives exactly one `error.captured` line on stderr with no message text, no database host and no
  database user, and exit 1 (on main no such line was written).
