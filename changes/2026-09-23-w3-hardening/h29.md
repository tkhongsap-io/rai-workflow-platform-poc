# H29: Draft editor only for users who can edit; no stale 'Draft saved' notice on another version

The final walkthrough re-verification on main `dfe84b3` found both issues. Both still reproduced on `dfe84b3`: the new browser assertions below failed before the change.

## Findings addressed

- **The draft editor's Change, Save and Submit controls were shown to users who cannot edit the draft (medium).** Admin, every lane reviewer, and the DPO + HR SPOC on a CM case (RAI-2000-0003, where she is not SPOC) all saw the full editor. The server answered their `PUT` with 403. Now the case screen passes `canEdit` to `PackEditor`, and only a writer of the case gets the controls. `canEdit` comes from the web predicate that already expressed the W0-05 `WRITE_ROLES` rule on a case: an owner grant on the case's business owner, or a `bu_spoc` grant for its BU. That predicate was named `canProposeFixedOnCase`. It is now `isCaseWriter`, because it serves edit, submit and propose-fixed alike. There is no second copy of the policy table. Anyone else sees the settings as a disabled fieldset, the nine slot rows with their files, and one line: `pack.read_only` ("Only the case owner or the business unit's SPOC can change this draft", in both catalogues). They get no Change, Save, Discard or Submit control.
- **'Draft saved (revision N)' carried over onto the version 1 page (low).** Each `Notice` now names the route it belongs to (`versionId`, undefined for the draft). A route change clears the notice unless it names the new route. The submit notice names the version it opens, so "Version N submitted" still shows there. This replaces the editor's `key.startsWith('pack.')` filter.

The server is unchanged. It is still the authority, and the new browser test checks that a reader's forced `PUT` is still refused with 403.

## Tests (fail before, pass after)

- `tests/browser/w1-int-06-case-pack-versions.spec.ts`, new test "the draft editor is offered only to the case owner or its BU SPOC; everyone else reads the draft". Three users get the editor: the owner and `fx-user-spoc-cm` on RAI-2000-0003, and `fx-user-dpo-spoc-hr` on the HR case RAI-2000-0005, which she edits as SPOC. They see nine Change buttons, Save, Discard and Submit, and no read-only line. Five users read the draft on RAI-2000-0003: AI CoE, DPO, IT Security, Admin and `fx-user-dpo-spoc-hr`. They see the read-only line, nine rows, the slot 1 file link and the slot 7 state, and no action cell, Save, Discard or Submit. For each of them the forced `PUT /draft` answers 403. The test ends with an axe audit (`draft-read-only-th`). Before the change the three editor rows passed and the test failed at `fx-user-ai-coe`, because the read-only line did not exist.
- `tests/browser/w2-int-journey.spec.ts`: after the owner saves the successor draft, the spec opens v1 from the version navigation and then goes back to the draft. The saved notice must be absent both times. Before the change: `getByText('บันทึกฉบับร่างแล้ว (ฉบับแก้ไขที่ ')` expected 0, received 1 on v1.
- `web/src/screens/case/view-model.test.ts`: `isCaseWriter` is true for the owner and the CM SPOC. It is false for another owner, for the owner's subject without an owner grant, for the SPOC of another BU, and for each reviewer and Admin.
