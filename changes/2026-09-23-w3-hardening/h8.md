# H8: Ready uses the approver's decision-time scopes; disposition stamps minted after the lock; observed_qc_run_id FK

## Findings addressed

- **Ready's self-approval recheck used the approver's current grants (workflow-core, medium).** W0-06 section 6, condition 4 says "at decision time". The check looked the approver up in the fixture identity list and then in their newest `session.principal`. A grant change made after the approval could therefore leave a fully approved, fully dispositioned case `in_review` for good, with no diagnostic. Migration 0008 adds `lane_decision.actor_scopes` (jsonb NULL). Both decide actions now write `ctx.actor.roles` into it. `evaluateReadyPredicate` runs `isOwnerOrSpocOnCase({ subjectId, roles: actorScopes }, facts)`. For a row without a snapshot, which only SQL can write, it keeps the fallback: the decision counts as a leak when it names the case owner or records `actor_role` `owner` or `bu_spoc`. A blocked leak is now visible: the not-ready `ReadyEval` names the lanes in `selfApprovedLanes`. Before this change, that result could not be told apart from an empty "not ready".
- **The disposition stamp was minted before the case lock (workflow-core, low).** `recordDisposition` took its timestamp from a process-global monotonic clock before the case lock. A request stamped earlier could commit later and sort before a disposition it never saw. `recordDisposition` now mints the stamp inside `apply()`, under the lock, as `max(clock, latest.created_at + 1 ms)`. `latestDispositionKind` became `latestDisposition` and also returns `created_at`. The same stamp is used for the disposition id, `created_at`, the audit `occurredAt` and Ready's `occurredAt` and `recordedAt`. `ctx.now` for the idempotency row stays the plain clock value.
- **FK from `lane_decision.observed_qc_run_id` to `qc_run(id)` (F1 optional hardening).** Added in migration 0008. W0-04 had documented the column as an FK, but no constraint enforced it.

The W0-04 column notes now describe `actor_scopes`, the FK and the stamp rule. The hardening `spec.md` records the schema change. The append-only trigger is row-level (`BEFORE UPDATE OR DELETE`), so it covers the new column. The immutability test now also tries to UPDATE `actor_scopes`, and it shows the FK rejecting an invented run id.

### Tests that fail before and pass after

- `w2-06-ready`: approve DPO, then add a CM `bu_spoc` grant to the DPO's session, then run the other two approvals. Before this change (with the session lookup that production identity modes used), Ready stayed false. It now applies.
- `w2-05-dispositions`: the owner's `fixed_proposed` starts first and waits for a pool connection. The reviewer's `waived` starts later and commits first. Before this change, the proposal sorted before the waiver, and the following `fixed_confirmed` returned `422 fixed_confirmed_without_proposal`. Now the order is `waived`, `fixed_proposed`, `fixed_confirmed`.
- The "BU SPOC approval inserted by SQL" test now covers both paths: a row that carries the SPOC's decision-time grants, and a row with no snapshot that records `bu_spoc`. Each one blocks Ready, and `selfApprovedLanes` is `['dpo']`. The old row (SPOC subject, `actor_role` `dpo`, no snapshot) was caught only by the fixture-list lookup. Under the specified fallback it would not block, so the test now inserts the snapshot that `approveLane` would have written.
- The frozen-clock monotonic test is unchanged and passes because of the +1 ms.

## Fix round 1

The reviewer found that no test read back the `actor_scopes` that the decide actions write. If the write were lost, Ready would quietly fall back to `actor_role`, and every test would still pass.

- `w2-06`, grant-change test: after the DPO approval, the `lane_decision` row's `actor_scopes` deep-equals the DPO fixture user's roles.
- `w2-03`, concurrent send-backs: both rows' `actor_scopes` deep-equal their actors' roles. The send-back write stays, because the column records the actor's grants at the time of every decision, not only approvals.
- Mutation check: with `insertLaneDecision` writing `actorScopes: null`, those two tests fail (14 pass, 2 fail). With the write restored, all 16 pass.
- The full suite reran with the same commands and environment as above. The results match the table above: unit 569/569, integration 310/310 with 0 skipped, browser 172 + 48, root 22/22, links 0 broken, frozen source matches, diff check clean. `origin/main` is still at 1b4d49e.
