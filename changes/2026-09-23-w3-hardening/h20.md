# H20: Shared workflow refs and remaining dead code

This batch only simplifies. Behaviour stays the same, and the proof is that every suite passes with its tests unchanged. No test file changed.

## Findings addressed

1. **workflow-core simplify and architecture simplify: helpers copied into each workflow service.** Checked on main `cf87c13`. The same helpers were written out several times: `caseRef` four times (versions, workflow, findings, ready), `keyRef` with `AUDIT_REF` three times, `refreshPathFor` four times (only the versions copy handled drafts), and the UUID regex three times (versions/repository, pack/repository, authz/middleware). `ActionContext` was declared five times, `REASON_REQUIRED` twice (plus one literal), and 22 nine-line `new StaleVersionError(staleDetails(...))` blocks.
   - The new `server/src/workflow/refs.ts` holds one copy of each: `isUuid`, `keyRef`, `caseRef`, `versionPath(caseId, version)` (the draft-aware form, built on `notifications/outbox.ts` `caseVersionPath`), `staleDetails`, which moves here from `cases/service.ts`, and `staleAt(reason, guidanceKey, version, caseRow)`. `staleAt` returns the `StaleVersionError` with `caseRow.rowVersion` and `versionPath(caseRow.id, version)`.
   - These files now import from `refs.ts`: versions/service, workflow/service, findings/service, workflow/ready, qc/orchestrator, artifacts/pipeline (one Ready-closed block), versions/repository, pack/repository, authz/middleware and findings/routes. cases/service and pack/service import `staleDetails` from it but keep their own `/cases/{id}` refresh path, because that is the draft editor for every guidance version.
   - `grep -rnE '0-9a-f\]\{8\}' rai-web/server` prints only `workflow/refs.ts`.
   - `ActionContext` is exported once, from `versions/transaction.ts`. `WorkflowActionContext` extends it, and the keyed services pass `{ ...ctx, action, ... }`. cases/service and pack/service import the same type.
   - `REASON_REQUIRED` is defined once, in `pack/slots.ts`. `versions/freeze.ts` and `findings/service.ts` import it.
   - **The refresh path does not change anywhere.** The workflow, findings and orchestrator copies always used the version page, while `versionPath` uses the case page for a draft. Every version they pass is submitted: the current version, the named version once it equals the current one, or a finding's version (findings come only from the submit and approve-attempt runs). `current_version_id` only ever names a submitted version. Only `closeDraftOnCase` sets it, straight after `freezeDraft`. So `assertDecideTarget`'s `named.submittedAt === null` branch and `loadOpenSubmittedTarget`'s `version.submittedAt === null` 404 could not run: `current.id !== named.id` had already answered. Both branches are deleted, and a comment records why.
   - `assertDecideTarget` and `loadOpenSubmittedTarget` stay separate, as the finding asks.
   - The audit snapshot is unchanged: the `caseRef` and `keyRef` bodies in `refs.ts` are byte-identical to every copy on main (checked with a script against `git show origin/main:`). The w1-00 audit tests and the w2 tests pass with no assertion changes.
2. **workflow-core simplify (remainder).**
   - `versions/service.ts` passes `laneMappingVersion: CURRENT_LANE_MAPPING.version` to `openLanesOnSubmit` (the value it has just frozen) and drops the `laneMappingVersion === null` throw.
   - `requireNamedArtifactFeedback` keeps only the blank-deficiency check and its `send_back_artifact_required` message key at `body.feedback.items[i]`. `SendBackLaneRequestSchema` already rejects a missing feedback, an empty `items` array (`minItems: 1`), a missing slot and an empty deficiency (`minLength: 1`), and `w2-02` still gets 422 for `items: []`. The function is no longer exported, because nothing else imported it.
   - The `db/transaction.ts` header now points at `versions/transaction.ts` instead of narrating which ticket added what. The `pack/qc-trigger.ts` header says why the no-op is bound: the orchestrator runs only the `submit` and `approve_attempt` triggers, and per-upload QC on a draft belongs to W4, which is not authorized.
   - Already done on main, so skipped here: both `void LANES;` lines (H9, #140), `failAfterFirstLaneOpenNotification` and its nodeEnv plumbing (H13, #145), and the shared notification insert (`enqueueCaseNotifications`, H13).
3. **workflow-core/queue-sla (remainder): `deskStatusFor` at versions/repository.ts and ready.ts.** Already done on main by H3 (#137): `closeDraftOnCase` uses `deskStatusFor('in_review')` and `applyReadyIfHeld` uses `deskStatusFor('ready_for_launch')`. No change needed.
