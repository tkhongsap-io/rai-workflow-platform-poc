# H14: browser evidence harness

Tests only; no product code changed.

## Findings addressed

1. **The W3-INT journey server forked the process harness.** `tests/browser/support/journey-server.ts` had its own
   stdout/stderr splitter: `Buffer#toString` per chunk, so a Thai character split across chunks was corrupted, no
   log-leak audit on stop, and the raw captured output was put into its error text. It now uses
   `attachCapture(child)` from `tests/support/process.ts`, like `startTestServer`. `stop()` awaits
   `capture.stop()`, which escalates to SIGKILL after the grace period. It then runs `assertNoLeak` over the captured
   lines and throws on a non-zero exit. `capturedLines()` returns `structuredClone(capture.lines)`. A startup failure
   reports the captured line count, not the output. Every journey-server spec is now leak-audited on stop: W3-INT
   journey, ready-readonly, desk-health and fault controls.
2. **Hard-coded port 58859 in the Ready read-only spec.** `startJourneyServer(env)` now takes a free loopback port.
   The explicit `assertNoLeak` after `server.stop()` is gone because `stop()` runs the audit itself.
3. **Keyboard reach helpers were copied into three specs.** The copies were `w3-int-journey` (`reach`, 120 steps),
   `w3-int-07-desk-health` (`reach`, 60 steps) and `w3-int-ready-readonly` (`activate`, 120 steps). They are
   replaced by `tabTo(page, target, maxSteps = 120)` in `tests/browser/support/keyboard.ts`. It also checks for a
   visible focus ring on every element Tab passes through, not only the target. The copies checked the target
   alone. The journey's `activate`, `type`, `select` and `radio` wrappers stay. No screen had a missing focus ring.

## What got smaller

- The 6 touched harness and spec files: 59 insertions, 87 deletions before the new regression test. One copy of the
  line splitter and three copies of the Tab loop are gone.

## Regression test

`tests/integration/w3-int-browser-lifecycle.test.ts`: "journey startup failure reports a line count, never the raw
captured output". The test starts the journey process with a mail sink path containing the
`RAI-DESK-SYNTHETIC-FIXTURE` canary, so the process fails before it reports ready. Before the fix, the rejection was
`Journey process exited: <stack trace with the canary path>`, and the test failed. After the fix, the rejection is
`Journey process exited; captured line count N`, and the test passes.
