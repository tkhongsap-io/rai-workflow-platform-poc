# H23: Shared integration app harness, part 2: move the remaining suites

## Findings addressed

The finding still applied on main `1c52b3f`: five suites still built their app inline.

- **Integration app wiring pasted into 9 files and drifting from start.ts (architecture simplify, medium; part 2).** H22 moved the four W2 suites. This batch moves the other five, `w3-01`, `w2-03`, `w2-09`, `w3-05` and `w3-03a`, onto `openFixtureApp`. It also moves `w3-hardening-idempotency-race`, the one remaining suite that pasted the whole deps block (it registered `decide` and `findings`). The acceptance grep needs it moved. Each suite now keeps only what is its own:
  - `w3-01` and `w3-05`: the Songkran clock, which each test resets and some advance. `w3-05` also keeps its unscripted runner.
  - `w2-03`: a fixed clock.
  - `w2-09` and the idempotency race: a fixed clock and a runner scripted for every fixture case.
  - `w3-03a`: a fixed clock, an unscripted runner and its memory mail sink.
  - Clocks: fixtures still load at each suite's old start time, and the app clock starts one minute later, as in H22. `w3-03a` never advanced its clock, so its app clock stays at 04:00 and its fixtures now load at 03:59.
- **What the harness gained, and why.**
  - A `mailSink` option. It is a factory like `qcRunner`, so `w3-03a` returns the sink it creates for each test. With a sink bound, `composeAppDeps` wires case mail and the daily digest, as `start.ts` does. The digest is new for `w3-03a`: before, the suite bound only the notification worker. At the suite's clock, the startup digest finds no breach and sends nothing, so every mail count stays the same.
  - `rebuildApp` now takes named overrides, `{ qcRunner?, mailSink?, laneOpenRecipients? }`. `null` binds no runner or no sink.
    - `w3-03a`'s old `build({ auto: false })` is now `rebuildApp({ mailSink: null })`.
    - Its rollback build is now `rebuildApp({ laneOpenRecipients: REPEATED_DPO })`, which repeats the DPO address so the second outbox insert breaks the unique key.
    - `w2-05`'s two positional calls become `{ qcRunner: null }` and `{ qcRunner: delayed }`.
  - `capture` now lives for a whole test, not for one app. `w3-03a` kept one log buffer for each test across its rebuilds, and its leak and `mail.sent` checks read it. The other suites filter by correlation id or check for leaks, so they see the same lines or more.
  - `beforeEach` closes the previous test's app before it resets the database. `w3-03a` did the same, because the app's automatic mail worker may still be writing the rows the reset removes.
- **w3-03a**: its own dispatcher (`notifications`) and the W3-04 `retryWorker` were the same `createNotifications` call. They are now one `dispatcher(mail = sink, clock = now, database = db.app)` on the current app's `diagnostics`. Its four hand-written log parsers are now `capture.lines()` and `capture.text()`. The replay test makes its own temporary directory and removes it, because the suite no longer has a scratch directory.
- **Not moved.** No suite under `tests/integration` composes the full production deps block inline any more: `git grep -n "sendBackRecipientsFromIdentities" rai-web/tests/integration` prints nothing. These suites still call `buildApp`, each for a reason:
  - The W1 suites (`w1-01`, `w1-02`, `w1-03-helpers`, `w1-04`, `w1-05`) and `w2-01` each register only the groups of their ticket.
  - `w1-12-harness` builds from configuration alone.
  - `w3-03b-digest` restarts its app on a digest clock.
  - `w3-int-log-coverage` only writes a stub `app.ts` into a temporary folder.
