# H2: Approve requires the latest lane-QC run

## Findings addressed

- **Approve accepted any qcRunId (workflow-core and architecture, duplicates).** `approveLane` now checks, under the case lock and after `lane_already_decided` (W0-06 §5.2 row order), that `qcRunId` names the latest `approve_attempt` run for (version, lane, rule revision). With no run the result is `422 invalid_input` at `body.qcRunId` with `error.invalid_input.lane_qc_not_run`. With a run that is not the latest the result is `409 stale_version`, reason `qc_run_superseded`, plus guidance and a refresh path. A latest run with status `unavailable` is accepted. `requireQcRunId` is now only the format check before the transaction, and its comment says so.
- **W0-06 §10 tests that were owed.**
  - W2-02: approving with another lane's run gives 422 `lane_qc_not_run`. Approving with an earlier unavailable run after a re-run gives 409 `qc_run_superseded`. The `lane_decision`, `audit_event` and `notification` counts are unchanged after each. The latest run then approves. A separate test shows that a latest unavailable run can be approved.
  - W2-05: send back, resubmit N+1, then dispose a finding of N. The result is 409 `version_superseded`, with `current` pointing at N+1. No disposition event and no audit row is written, and the finding row is unchanged.
  - W2-06: a gated submit-QC run and the third approval run in `Promise.all`. A held case-row lock makes the QC persist queue first. Its finding blocks Ready, so `ready_at` stays null. If the order is reversed, the approval sets Ready and the QC result is refused, which shows the ordering is real.
- **Every approve helper uses a real run.** The helpers in w2-02/03/04/05/06, w2-int-negatives and w3-03a POST `…/lanes/:lane/qc-run` and use the returned `runId`. `randomUUID()` is no longer used as a `qcRunId`. A forbidden or stale approval names a real run that a lane reviewer saw.

The in-memory API substitute keeps its own approve logic. It never counts as evidence. H8 owns the optional FK on `lane_decision.observed_qc_run_id` and its migration. This batch changes only the stale column comment.

## What got smaller

- `ruleRevisionOf` moved from `qc/orchestrator.ts` to `qc/repository.ts`, next to the latest-run lookups that take it. The orchestrator only imports it now.
- `workflow/service.ts` drops its private UUID regex and uses `isUuid`.
- `w2-06-ready.test.ts` drops the unused `withQc` flag and the fixture-case map. Only the vendor case is scripted, so lane QC is clean everywhere else. `w2-02` uses an unscripted runner.
