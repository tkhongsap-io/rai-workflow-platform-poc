# H21: SPA: one 401 handler instead of onUnauthenticated prop-drilling

## Findings addressed

- **web-ui simplify (low), narrowed to the 401 part: "Fetch, cancel and 401 boilerplate is repeated in 7 places, and onUnauthenticated is prop-drilled through 6 components".** Still present on main `180b07f`: `case-screen.tsx` built an `unauthenticated(err)` callback and passed it as `onUnauthenticated` through `CaseScreenBody`, `ReviewerWorkspace`, `FindingsList`, `FindingRow`, `DispositionControls` and `LaneDecisionActions`; `case-list-screen.tsx`, `new-case-screen.tsx` (twice), `queue-screen.tsx` and `desk-health.tsx` each repeated `err instanceof ApiError && err.status === 401 ? signedOut('revoked')`. The loaders stay per screen, as the batch specifies.

## Change

- `web/src/api/client.ts`: `api.setUnauthenticatedHandler(fn)`. `request` calls the handler on a 401 before the caller receives the `ApiError`, except for the sign-in flow's own routes (`GET /api/session`, `POST /auth/sign-in`, `POST /auth/sign-out`, `GET /auth/fixture/users`, `POST /auth/fixture/sign-in`), whose 401 means "not signed in" to that flow. Skipping the session probe is what keeps a first visit from reading as an expired session and the sign-in page from revoking itself.
- `web/src/session/session-provider.tsx`: registers the handler once, `() => signedOut('revoked')`. The unused `refresh()` (the provider's own per-call 401 check, called nowhere) is deleted.
- Screens: the `onUnauthenticated` prop and every per-call 401 check are removed; each catch now just records its error. After a 401 the router has already swapped the screen for sign-in, so that state belongs to an unmounted component. The disposition refetch in `reviewer-workspace.tsx` keeps swallowing its failure, now without the handler call.
- Behaviour: unchanged for every call that already handled 401. Two calls that previously swallowed a 401 now also drop the session, which is what the provider already documented ("a 401 on any call clears the session"): the locale switch's `POST /api/session/locale` and the artifact metadata read `GET /api/artifacts/{id}/meta`.
- Tests: `client.test.ts`: a 401 calls the handler for a desk call and for `setSessionLocale`, and never for the five sign-in-flow calls; the caller still receives the `ApiError`; a 403 never calls it. This test failed before the change (`client.setUnauthenticatedHandler is not a function`). `w1-int-07`: the first-visit test asserts that no `auth.session_expired` notice appears (the session probe's 401). A new test revokes the session on the server while the SPA still holds its copy, opens a case from the list, and lands once on `/sign-in?returnTo=/cases/<id>` with the expired notice. Signing in again returns to the case.

## What got smaller

Across `web/src`, excluding tests: 64 lines added, 101 removed (net -37). One `onUnauthenticated` prop is gone from six component signatures and their call sites, the `unauthenticated` callback is gone from the case screen, five inline 401 branches are gone from four screens, the dead `refresh` is gone from the session context, and several effect dependency lists are shorter. No new module was added.
