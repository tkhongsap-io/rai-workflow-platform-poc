# H5: reviewer case screen shows every stored finding of the lane, supports multi-lane reviewers, keeps focus

## Findings addressed

The three bugs come first, in the order the batch lists them.

1. **The reviewer workspace hid the lane's stored findings that its own lane-QC run did not produce (high, A08).** In lane-QC mode the workspace listed only `run.findings`, so a submit-QC finding stored for the lane never appeared. It still reproduced on main `8849961`; the branch is rebased on `1ab240b`. Owner submits `fx-case-missing-slot`, and submit QC stores `PACK-SLOT-MISSING` for `it_security`. The IT/Sec reviewer then saw zero finding rows and could approve past the defect. No screen offered a way to disposition the finding, so Ready could not be reached from the UI. Now `load()` always lists the version's stored findings, filtered to `owningLane === lane`, and the lane-QC run is kept only for its status and `runId`. `QcUnavailableBlock` renders above `FindingsList` instead of replacing it. When an unavailable run has nothing stored, the block renders alone, so the screen never also says "found no defects". After a disposition, the refetch applies the same filter for a lane (before, it did not refresh a lane's list at all). New browser case in `w2-int-09-disposition.spec.ts`: the owner submits `fx-case-missing-slot` with the scripted QC substitute bound (the real server's `QC_MODE=substitute`), and AI/COE and DPO approve through the API. The IT/Sec reviewer sees `PACK-SLOT-MISSING` on slot 7, approves, and records `fixed` by keyboard, and the case reaches Ready. Before the fix it failed at the row count (0, expected 1).
2. **The SPA took only the first lane grant (low).** `reviewerLaneOf` became `reviewerLanesOf(roles): Lane[]`, and `dispositionKindsForActor` checks `reviewerLanesOf(roles).includes(findingOwningLane)`. `CaseScreen` renders one `ReviewerWorkspace` per lane, each with a `lane` prop and the heading id `reviewer-findings-heading-${lane}` (the owner panel's id is `reviewer-findings-heading-owner`). The guards that do not depend on the lane (latest version only; the case's owner or BU SPOC never reviews it, D05) moved into one function, `reviewerWorkspaceLanes`. It returns the lanes to render, or `[null]` for the owner/BU-SPOC proposal panel. This replaces `findingsLane`. Calling `findingsLane` once per lane would have drawn a proposal panel for every lane of a self-excluded multi-lane principal, and none for a plain owner. `decidableLane` became `laneIsDecidable({ lane, view, hasOpenDraft })` and keeps only the checks that depend on the lane. New unit test: a principal with the `dpo` and `it_security` grants gets both workspaces and can disposition in both lanes but not in `ai_coe`. No `allowedActions` field was added.
3. **Approve, send-back and a Ready disposition dropped keyboard focus to `<body>` (medium).** The success notice has `tabIndex={-1}`. For `review.decided.*` keys it has a stable ref callback that focuses it when it mounts after the screen reloads. `w2-int-07` asserts the notice `toBeFocused()` after the keyboard approve and after the send-back. The new `w2-int-09` case asserts it after its approve and after the Ready disposition. After send-back, the `w2-int-07` spec reaches the version navigation, which sits before the notice, through H14's `tabTo` helper. That helper allows the Tab order to wrap around. The new case uses `tabTo` too, so it waits for the reloaded lane findings before it tabs. The optional "keep the previous result while reloading" was not done.

Simplifications:

- `canSeeFindings` is gone from `DispositionControls`, `FindingRow`, `dispositionKindsForActor` and its tests. It was always `true`; the `false` test case is dropped.
- `runLaneQc` sends `expectedVersionOf(version)` instead of a hand-built literal.
- `Notice` is one `{ key: 'pack.saved' | 'pack.submitted' | 'review.decided.approve' | 'review.decided.send_back' | 'review.decided.ready'; params }` type in `view-model.ts`. `PackEditor` uses it instead of its own copy.
- `CaseScreen` uses `useSignedInSession()`, and the `session !== null` branch is gone.
- A QC outage with no reason maps to the new `review.qc.reason.unreported` (en "not reported", th "ไม่ได้ระบุสาเหตุ"). It no longer claims "not configured".
- `ReviewerWorkspace` lost its wrapper component, the separate overlay state, `mergedKinds` and the two copies of the list-to-map code. One `laneFindings` helper serves both the load and the refetch, and a recorded kind is written straight into the loaded state until the refetch lands.
- Copy and catalogues: ` (D11)` is removed from `pack.stage_context_hint` in en and th. `case.placeholder_title`, `case.placeholder_body`, `operator.field.case_id`, `operator.field.kind` and `operator.field.version_id` are deleted from both catalogues; nothing read them. The `auth.*` keys stay. The unused-key lint was not added.
- Headers (comments only): `reviewer-workspace.tsx`, `disposition-controls.tsx`, `case-screen.tsx`, `finding-list.tsx`, `lane-decision-actions.tsx`, `operator-labels.ts`, `dialog.tsx` (the header and the `className` doc on line 37), `view-model.ts`, `view-model.test.ts` and the two browser specs. They now state the invariant, with no ticket IDs and no "Issue #35 stays open". `error-notice.tsx` belongs to H12 and is untouched.

Issue #35 is not decided here. The lane filter uses the `owningLane` the server stored. Slot-5, slot-9, pack-level and QC-unavailable findings keep whatever the server assigns (see H7), and the UI assigns no lane.
