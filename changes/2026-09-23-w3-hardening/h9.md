# H9: Disposition route authorization and route-guard consolidation

No 500s for bad ids, and no hard-coded owning lane.

## Findings addressed

- **workflow-core / security-crosscut (medium): malformed ids reached Postgres as uuid casts.** On main, `POST /api/cases/not-a-uuid/findings/<id>/dispositions`, a `findingId` of `x`, and `POST …/versions/x/lanes/ai_coe/qc-run` each returned 500 `internal_error`. The new tests reproduced all three before the fix. The disposition handler now treats a non-UUID `caseId` as a missing case: it runs the same unresolved probe the middleware uses, so an actor without `all_cases` gets 403 and anyone else gets 404. A non-UUID `findingId` is treated as a missing finding. The qc-run handler throws `NotFoundError('version')` for a non-UUID `versionId` before it calls `runAndPersistLaneQc`.
- **architecture (low): an unknown finding was probed against a hard-coded `owningLane: 'ai_coe'`.** On main, a DPO or IT/Security reviewer got 403 and a false `authz.denied` line for a random finding id, while AI/COE got 404. The handler now probes every lane in `LANES` and allows the request if any probe allows. Otherwise it denies with the first probe's reason. The `'ai_coe'` literal is gone and no owning lane is assigned, which is consistent with open issue #35. The substitute twin (`fixtures/src/substitutes/api/routes-review.ts`) had the same literal and now uses the same all-lanes probe.
- **security-crosscut (low): the authorize → `authz.denied` → 403 block was copied five times.** `authz/middleware.ts` now exports `denyUnlessAllowed(emitter, actor, action, target, log)`. The middleware's own final decision and its unknown-lane probe, the disposition route, and both body-driven checks in `cases/routes.ts` now call it. `authorizeFinding` and the three inline log blocks are deleted. In `cases/routes.ts`, `authorizeFacts` is now a one-expression wrapper around `denyUnlessAllowed` that sets `targetType: 'case'` for its two callers (create and the post-edit check). `emitDenied` stays private: it is the one place the line is written, and `denyUnlessAllowed` plus the `cross_site` and unknown-`:lane` refusals call it.
- **security-crosscut resilience (low): public routes resolved the session against Postgres.** The `onRequest` hook now returns for `auth.kind === 'public'` before it reads the cookie. The `/healthz` and `/readyz` special case and the later public return are deleted. Static assets, the SPA shell and the sign-in routes no longer run a session SELECT or a `lastSeenAt` UPDATE, and they keep serving during a session-store outage. Risk check: no public handler reads `request.principal` or `request.session`. Sign-in creates a session and never inspects an existing one, and `static.ts` and the probes read neither. W0-10 `request.completed` now says the actor fields are absent on public routes.
- **security-crosscut simplify: the hand-written cookie parser was never called.** `parseCookieHeader` is deleted, along with the comment claiming `@fastify/cookie` "may run after this one". The hook reads `request.cookies[deps.sessionCookieName]`. The substitute's comment that pointed at the deleted function is corrected.
- **security-crosscut / architecture simplify: impossible-state guards were written four different ways.** `authorizedActor(request)` returns `{ principal, role, facts }` and throws `Error('route reached without authorization')` when `principal` or `authz` is missing. It replaces the guards that answered a wiring bug with a misleading 404 `case` in pack, versions and workflow (two), the local `actorOf` in artifacts, and the `!` assertions in cases and queue. `void LANES` is deleted from `workflow/routes.ts` (the import went with it) and from `findings/routes.ts` (the import stays because the all-lanes probe uses it).
- **Dead code that followed:** `recordDisposition`'s `isUuid(findingId)` guard is deleted. Its only caller now reaches it with the id of a finding it has already read.

## What got smaller

Production source (`server/src`, tests excluded) is 120 lines added and 187 removed. The findings route alone is 35 added and 77 removed. One export and one private helper are gone (`parseCookieHeader`, `authorizeFinding`), along with four hand-rolled `authz.denied` blocks, eight guard lines and two `void LANES`. The two new exports each replace at least four copies.

## Tests

- `rai-web/tests/integration/w2-05-dispositions.test.ts`, new describe block (2 tests). The rows went into the existing W2-05 file rather than a new file, so they reuse its app, fixture and QC setup instead of copying about 150 lines of it.
  - A `caseId` of `not-a-uuid`, a `findingId` of `x`, and qc-run with a `versionId` of `x` each return 404 `not_found` with the right `resource`. Each emits a single `error.captured` line with `code: not_found` (never `internal_error`) and no `authz.denied`. The owner on `not-a-uuid` gets 403, with an `authz.denied` reason of `scope`.
  - A random finding UUID with kind `waived` on an in-scope submitted case returns 404 (`resource: finding`) for the DPO, IT/Security and AI/COE reviewers, with no `authz.denied` line. Admin gets 403 with reason `role`.
  - Before the fix: both tests failed (500 on the malformed case id; 403 for the DPO on the unknown finding). Once the disposition fix was in, the qc-run row still returned 500 until its guard was added. After the fix: both pass.
- `rai-web/fixtures/src/substitutes/api/review.test.ts`, `disposition` block (fix round 1): the substitute mirror of the unknown-finding row. It returns 404 `not_found` (`resource: finding`) for the DPO, IT/Security and AI/COE reviewers, with no `authz.denied` line, and 403 with reason `role` for Admin. With the old `'ai_coe'` probe restored in `routes-review.ts`, it fails (the DPO gets 403). With the all-lanes probe, it passes.
- `rai-web/server/src/observability/http.test.ts`:
  - New test: a public route with a session cookie returns 200 while the session store throws, with no store call and no `error.captured`. It fails on the old hook (verified by temporarily restoring the old early-return placement) and passes on the new one.
  - The existing "request.completed names the signed-in actor" test used a public route only as a vehicle. It now declares `auth: { kind: 'session' }`, because public routes no longer resolve the session by design. Its assertions are unchanged.
