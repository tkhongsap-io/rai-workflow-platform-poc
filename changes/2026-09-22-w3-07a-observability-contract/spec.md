## Shared surfaces

`rai-web/shared/src/schemas/observability.ts` defines TypeBox readiness/operator/safe-error schemas and inferred types; `schemas/queue.ts` re-exports them as W0-10's W3 surface. Consumer routes validate/serialize through the schemas, not unchecked database objects. The operator route remains Admin-only via operator.view; readiness has no recipient/name/path/error text. Identity failure codes use the existing adapter vocabulary, including the session-lifetime refusal. Build values are dev or commit hash and numeric schema version/unknown. Computed readiness uses the unchanged W0-10 predicate, 2-second probes and 5-second cache; QC outage does not gate it. Schema validity alone does not prove the predicate.

Operator arrays are capped at 100, with stable ID tie breaks on the existing sort. `unavailableQc.reason = unknown` means the stored reason is NULL, never an inferred timeout. `failedMail.failureCategory` is present exactly when status is failed and equals mail_delivery_failed; queued retry rows omit it. `lastErrorCode` retains the safe delivery cause. No duplicate category column. Internal-error counters group by code in the public report; the private counter may additionally group by stackHash. Recipients are allowed only in the authorized operator response, never logs.

## Typed safe errors and OBS reconciliation

SafeErrorFieldsSchema is the closed category union for error.captured payload data. The consumer adds code equal to category, the fixed W0-06 HTTP classification and a server-owned route pattern (if HTTP). Unknown fields are rejected in test/CI and dropped in production. The W0-10 catalogue registers fieldPaths, reason, caseId, expectedVersionId, currentVersionId, qcRunId, versionId, notificationId, attempts, errorCode, targetType, slot and sizeBytes in addition to the original envelope fields. Category-specific validation prevents unrelated fields from riding along.

For logs, fieldPaths is a unique bounded list of the canonical input surfaces body/querystring/params/headers. Detailed field paths may remain in HTTP validation responses, but arbitrary unknown property names are never copied into logs. Auth actor/action detail stays in the separate authz.denied event. Unsafe MIME declarations are not echoed into error.captured. Internal stacks are arrays of bounded relative module/line/column frames: no message, function text, absolute home path, URL or error.name. The capture consumer accepts module names only from its built source-file inventory; the schema alone is not a sanitizer. Unrecognized frames are dropped. Hash only sanitized frames. No raw Error object reaches Pino. The existing pack/service.ts upload-trigger catch emits the legacy qc_upload_trigger category and error.name; W3-07a runtime integration must replace it with the typed internal_error capture. It is not fixed or certified by this prerequisite.

OBS-13 proves actual HTTP categories unauthenticated, forbidden, stale_version, invalid_input, unsafe_upload, not_found and internal_error with one error.captured event, correct level/status and matching response header/body correlation. qc_unavailable is tested through capture with the synthetic runner; no new synchronous endpoint is created. mail_delivery_failed is captured from W3-04's job context with HTTP classification 502 but no HTTP response to the already committed action. One terminal domain mail.failed event and one error.captured event are distinct required records, not duplicate failures; OBS-09 counts mail.failed only. OBS-10 counts qc.run.unavailable once per newly persisted run, not per replay or operator read.

## Persistence and digest producer contract

0007 adds nullable qc_run.unavailable_reason with bounded values. Historical NULL remains NULL; no backfill and no rewrite of frozen rows. New QC writer consumers supply a reason on new unavailable rows. Completed rows must have NULL. Existing writers remain compatible until their integration lands.

operator_job_run stores job=sla_digest, a persisted Bangkok digest_day, correlation_id, started_at, finished_at, status, breach_count, error_stage and bounded error_code. W3-03b alone produces digest jobs. Insert running before query; complete or fail once; identity/day/start/correlation cannot change and terminal rows cannot change or be deleted. After a crash an unfinished row stays running; the operator does not invent completion. Safe stages query/render/enqueue and codes query_failed/render_failed/enqueue_failed/internal_error never contain provider exception text.

operator_job_notification has foreign keys to job run and notification, unique notification_id, and UNIQUE(digest_day, recipient). Its insert guard checks the persisted run is running, day matches, notification is sla_breach_digest with null case/version and lane '-', recipient matches and correlation matches. Link plus outbox insertion occur in one transaction. A deferred constraint requires every new digest notification to have a link at commit. Links are append-only. The existing NULL-version notification uniqueness remains unchanged; this day+recipient index is the digest dedup authority. A retry sends the same row and preserves its run/correlation; it does not create a new link. A second scheduled run on the same Bangkok day skips recipients already linked; any racing duplicate insert rolls back its outbox transaction. New days may notify the same address. A run's notificationIds includes only its own committed links; a duplicate-only run completes with an empty list and does not steal old provenance. Delivery reads provenance by joining the notification ID to its persisted run. No caller-supplied UUID is proof of an authorized job.

DigestJobProvenanceSchema defines kind=sla_digest_job, jobRunId, digestDay, correlationId. This branch does not change CommittedEvent or loosen mail-sink validation. Ordinary mail keeps mandatory auditEventId. Before W3-03b consumes job provenance, a coordinated mail contract must introduce a discriminated digest variant and update the existing sink validator/tests together. The server composer must resolve the SQL linkage before calling the sink; the sink validates the variant and day/correlation consistency, not database authorization itself. Regression tests through the existing memory/file sinks must reject missing/forged ordinary audit provenance, digest-as-ordinary, ordinary-as-digest, malformed/mismatched job provenance, and server attempts with absent/mismatched SQL runs. Positive authorized digest, same-day duplicate and next-day delivery must pass. Hypatia retains composer ownership; no consumer is implemented here.

## Durable late QC and integration acceptance

qc_late_result is an append-only operational record with a unique attempted qc_run_id (not a qc_run foreign key), version foreign key, trigger, optional triggering lane, result status, refused finding count, timestamp and original correlation. The version must already be Ready. caseId is derived from the version join. The lane is only the triggering lane if known, never an invented owning lane. After the Ready recheck refuses append, persist this record in a separate committed transaction and emit one qc.run.late; do not insert qc_run/findings or business audit. Replays use the same attempted ID and do not duplicate records/events. DeskHealthReport.lateQc exposes at most 100 newest rows. W3-INT must hold a synthetic run, make the version Ready, release it and prove zero findings appended, one durable refusal and matching log/report correlation after restart. This remains mandatory, not deferred away.

Submit-trigger QC is W3-INT integration acceptance: after successful submit commit, invoke the injected synthetic runner, persist its final run in a separate case-locked transaction with the submit correlation, and prove timeout yields one unavailable run/log/operator entry. A rolled-back submit produces no run. The response remains a successful submit. Unavailable findings remain absent until the authoritative owning-lane rule exists; no lane is invented. W3-07a must not claim OBS-10 end-to-end before this integration passes. No real QC implementation or W4 acceptance is implied.

OBS-01–05/12/14–16 remain the W0-10 health, Admin policy, stack safety and suite-wide log obligations. OBS-06–08/09/11 require the actual workflow/composer/retry/digest consumers. Contract/schema/migration tests are prerequisites, not a substitute for those OBS proofs.
